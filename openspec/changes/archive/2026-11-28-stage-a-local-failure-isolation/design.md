# 阶段 A · 本地故障验证设计

## Context

[阶段 A 端到端验收](../../../docs/specs/stage-a-acceptance.md) 第 3 步用本地替身注入故障。已有串行工具批次与独立观察，新增验证接入同一 SDK 入口。

## Goals / Non-Goals

验证启动回执丢失、文件保存回执丢失、并行隔离及 Run 截止。跨进程恢复和通用写工具各自留在后续边界。

## Decisions

| 边界 | 实现 |
| --- | --- |
| 启动 | Mesh 以错误值携带响应丢失证据。SDK 映射为可识别的启动不明 |
| 工具副作用 | 测试替身保存到独立临时路径后丢弃回执。实际执行计数和环境释放分别断言 |
| 并行 | 用渠道暂停甲的工具，分别关闭和填满观察流。乙在甲释放前完成 |
| 时间 | Go 1.24 的测试时钟单独运行，生产 Run 继续沿用 `context` 和标准时钟 |

## Risks / Trade-offs

使用试验性测试时钟的用例单独开启编译开关。普通构建和运行保持现有 Go 版本及生产依赖。
