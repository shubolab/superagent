# 本地持久产物恢复规范

## ADDED Requirements

### Requirement: 按原回执恢复本地产物发布和结算

使用本地持久产物绑定的可恢复 Run MUST 固定原存储身份。收到含产物引用的可信回执后，当前运行器 MUST 核验原调用、封存元数据、完整正文和原预算，再接用或发布同一版本。工具结果、引用和扣减 MUST 一次提交。恢复沿用原绝对核对期限，且不得重发原工具。

#### Scenario: 原回执已落盘而正式发布尚未提交

- **WHEN** 写入进程封存产物并保存匹配回执，在产物变为可见前退出
- **THEN** 新运行器在原核对窗口内核验完整正文，发布同一引用，按已确认的实际原始输出和有界回执各结算一次
- **AND** 产物正文保留在原绑定中，模型和检查点只接收配对结果与引用

#### Scenario: 正式发布后但运行器结算前退出

- **WHEN** 产物已持久发布，运行器在工具结果与账本提交前退出或丢失确认
- **THEN** 后继使用同一已发布版本完成原结算，保留原到期时间。工具执行、可见发布及最终结算各一次

#### Scenario: 新代次接管时原产物已封存

- **WHEN** 当前所有者取得原接单代次对应的可信回执，旧运行器仍存活
- **THEN** 当前所有者只能确认原调用已持久封存的同一版本。旧进程的封存和发布提交被拒，原调用的派发与写入均不重复

### Requirement: 本地产物不可用时保护原工具事实

系统 MUST 区分待核对调用、已结算结果及已提交终态。未核验的产物不得进入待提交的工具批次。恢复继续依赖已结算产物时 MUST 先核验所需引用，匹配失败或超过原窗口即停止相关推进。产物失败不得触发原调用重发。

#### Scenario: 待核对的原结果缺少可用产物

- **WHEN** 原回执缺失，或其中的产物缺失、损坏、不匹配或已过期，且原核对期限到期或显式取消先发生
- **THEN** 按原 `CallID` 返回 `ToolOutcomeUnknown`，未完整批次不进入历史。无法核实的用量按原预留结算，继续派发和原调用重发均为零

#### Scenario: 已结算且续跑仍需使用的产物不可用

- **WHEN** 后继运行器从部分工具批次或下一轮模型意图前的检查点接续，且这一步依赖的已结算产物无法验证
- **THEN** 保留已提交的工具结算和历史，按产物不可用结束 `Failed`，原取消或 Run 截止已生效时沿用对应停止原因
- **AND** 不再次扣减该调用，也不派发依赖它的下一步

#### Scenario: 终态提交后产物遗失或过期

- **WHEN** Run 终态已提交，有效引用对应的产物随后遗失、损坏或过期
- **THEN** `ReadArtifact` 报告产物不可用，`Wait` 在结果保留期内继续返回原终态及原引用
