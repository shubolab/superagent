# 阶段 A · 本地纯文本 Run 任务

[包与最小接口](design.md) · [验收用例](specs/run-lifecycle/spec.md)

## 1. Go 结构和本地装配

- [x] 1.1 按设计建立 Go module、根包和三个内部包，定义公共 DTO 与最小接口。用外部包编译检查宿主能用根包类型实现 `ModelProvider`。
- [x] 1.2 实现进程内 Mesh 的普通请求与流路由，接上 `NewMesh` 和 `NewClient`，校验运行器、模型和可信主体配置。用本地替身验证绑定可解析、未知绑定明确失败、流顺序和关闭语义可传播。

## 2. Start 和纯文本模型推进

- [x] 2.1 实现 `Start` 的身份、输入和预算校验，固定受理快照，按主体和 `RunID` 去重。验收非法请求零模型调度、同请求复用及不同请求冲突。
- [x] 2.2 经 Mesh 发起一次 `Generate`，处理增量与 `ModelCompleted(stop)`，提交消息增量和终态。在运行器层用可控模型验证启动上下文和历史快照的隔离，并验证完整回复成功、提前 EOF 或异常完成失败。
- [x] 2.3 在模型派发前实施输入限额，在流和完整回复处实施输出限额。验收输入超限零模型请求，中文输出六字节达限可完成、五字节上限触发停止并关闭模型流。

## 3. Observe 和 Wait

- [x] 3.1 接入 `Observe`，按字节保留有界事件前缀。验收快速完成后首次观察、连续 `Seq`、终态后 EOF、关闭或取消解除阻塞、慢读溢出及第二次订阅拒绝。
- [x] 3.2 接入 `Wait` 和按标识取句柄，按主体和保留期读取终态。验收等待到期后可再取结果、多个等待者的快照相互独立、其他主体无法观察或等待该 Run。

## 4. Cancel 和截止时间

- [x] 4.1 实现幂等取消及 Run 到期的停止裁决，传递到模型流并释放阻塞。在可控模型上验证取消先到、成功先提交、Run 截止先到和跨主体取消被拒，检查停止信号、关闭和唯一终态。

## 5. 公开入口集成验收

- [x] 5.1 从 `NewMesh → NewClient → Start` 回归全部生命周期场景，再并行启动两路模型，验证取消一路只影响其自身。运行 `go test ./...` 和 `go test -race ./...`，核对事件、结果、模型调用次数和流关闭。
