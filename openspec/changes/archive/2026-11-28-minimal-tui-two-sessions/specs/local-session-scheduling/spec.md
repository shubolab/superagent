# 本地会话调度 · 受理进度

## ADDED Requirements

### Requirement: 可选的受理进度通知

SDK MUST 提供按 `RunID` 归属的可选受理通知。实际入队后交付 `queued`，调度器授予名额后交付 `admitting`，最后交付同一次启动的 Run 句柄或错误。阶段通知各至多一次且按序，通知未消费时调度和 Run 受理仍可推进。

#### Scenario: 排队后获得名额

- **WHEN** 启动请求进入本地等待队列，随后获得名额并受理
- **THEN** SDK 依次交付 `queued`、`admitting`、原 `RunID` 的启动结果。等待阶段尚无 Run 执行流

#### Scenario: 立即授予、拒绝或等待结束

- **WHEN** 当前有名额、队列已满，或等待中的调用取消或到期
- **THEN** 立即授予只交付 `admitting` 和启动结果。队列满只交付拒绝，取消或到期的等待项交付 `queued` 和相应错误
- **AND** 未启用调度的绑定只交付原启动结果

#### Scenario: 重试和慢消费

- **WHEN** 宿主暂缓处理通知，并以同一标识和请求重试启动
- **THEN** 首次调用的通知仍按原顺序可读。重试共享原启动结果，队列项和实际受理次数均不增加
