# 最小 TUI · 实现与验收清单

## 1. SDK 受理通知

- [x] 1.1 接入可选的受理通知通道。验证真实入队、授予、启动回执的顺序和归属，以及立即授予、队列满、取消、超时、重试和慢消费。

## 2. 终端与生命周期

- [x] 2.1 装配可启动的本地终端入口，打开两个会话并连接键盘与视图。用输入序列验证切换、草稿、状态栏、非空发送和同会话重复发送。
- [x] 2.2 按会话和 Run 更新实时输出，分别处理观察、等待和历史提交。验证后台连续收取、迟到事件、观察中断和保存失败。
- [x] 2.3 接入 `Esc`，以按键时的会话和 `RunID` 决定取消目标。验证等待取消、运行中取消，以及授予与取消竞争的各个结局。

## 3. 验收

- [x] 3.1 用伪终端驱动键盘及渲染，以真实本地 Mesh、临时会话存储和可控模型验证下列矩阵，记录对应的派发、订阅、取消和历史提交次数。
- [x] 3.2 运行全量 Go 回归和 race 检查，记录复验结果。

## 验收用例

单名额场景用同步点卡住甲的慢工具。双名额场景用同步点交替释放两个模型流。验收读取终端画面及 SDK 结果，排队和受理以调度事件对齐。

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| 受理通知 | 分别立即启动、排队后授予、满队列拒绝、排队超时和重复启动。延迟读取通知 | 有名额时跳过入队，排队时按序收到 `queued`、`admitting`、结果。拒绝与超时可辨。同一逻辑启动只受理一次 |
| 切换与草稿 | 在甲输入草稿，按 `Tab` 切乙并按 `Enter`，连续发送后切回甲 | 甲原草稿和历史仍在，乙只有一次启动。两条会话的当前标记与状态正确 |
| 单名额交接 | 甲占位，乙发送后等待，来回切换。先结束甲并暂缓保存甲的历史。另用零等待容量与短等待期限复验 | 乙从排队进入受理和运行。等待时无 Run 流或派发，甲历史待保存时乙仍自动收到输出。队列满和等待超时分别显示并恢复草稿 |
| 取消排队 | 甲仍占位，在排队的乙按 `Esc`，随后让甲结束 | 乙恢复本次草稿，历史版本保持原值。甲继续并结束，乙的派发数始终为 0 |
| 双流与取消隔离 | 让两边都输出。切到乙按 `Esc` 后立即切回甲，继续放行甲的输出 | 乙的原 `RunID` 收到一次取消，甲继续输出。再次切回可看乙自己的终态，每个 Run 的 `Observe` 只开启一次 |
| 取消与受理竞争 | 控制取消先到、授予先到及回执不明，注入迟到的入队事件 | 明确未受理时恢复草稿。已受理时只取消原 ID。结局未核实时保持待核对，新增派发为 0。迟到进度无法覆盖取消或终态 |
| 观察与历史收尾 | 令观察中断，再交付 `Wait`。另以存储故障模拟保存失败并重试提交 | 中断保留预览，终态以最终确认消息收束。保存失败前后旧版本一致，成功重试仅递增一次。另一会话继续更新 |
