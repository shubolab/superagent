# 阶段 C 首步 · 实现与验收清单

## 1. 本地历史

- [x] 1.1 建立主体与会话作用域下的持久索引和有界 Run 增量文件。用真实临时目录验证空会话、隔离、损坏错误、完整增量的历史窗口及容量上限。

## 2. Run 受理与接续

- [x] 2.1 接入会话内的 `RunID` 生成与待提交预约，固定版本、历史窗口及输入。用可控模型核对首个请求的消息顺序和重复输入次数，验证同会话忙与明确未受理后的释放。
- [x] 2.2 根据原存储、归属和请求摘要接续 Run。验证预约后尚未受理、已受理但响应丢失、同标识请求变化、结果过期和原存储不可确认的路径，并核对派发次数。

## 3. Run 结果提交

- [x] 3.1 用可信 `Wait` 增量增加封存及原子发布。验证并发重复提交、响应丢失重试、后续版本上的迟到重试，以及归属、增量和版本冲突。
- [x] 3.2 验证取消、失败和 `ToolOutcomeUnknown` 的历史内容。以等待超时、观察断连和取消尚未终止对照，断言这些事件独自发生时版本和消息保持原样。

## 4. 集成验收

- [x] 4.1 用同一宿主的独立进程、真实会话目录和阶段 B 绑定跑 C1–C3、C5。按落盘时点终止进程，核对重启后的版本、原回执和模型或工具派发计数。
- [x] 4.2 用同一主体和运行器、可控模型流及慢工具跑 C4。用同步点确认甲仍阻塞、乙已经推进，并验证两路历史、事件、取消和提交隔离。
- [x] 4.3 跑全量 Go 回归和 race 检查。记录 C1–C5 的实际存储与运行条件、关键计数和结果。

## 验收用例

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| C1 重启续聊 | 进程一提交 Run 甲后退出。进程二打开同一会话，启动 Run 乙 | 读到 v1，Run 乙的首个请求含甲的完整历史及乙输入各一次。乙提交后为 v2 |
| C2 受理状态恢复 | 分别在会话预约落盘后、B 受理后回包前退出。另跑原终态过期且未封存、原绑定变化 | 首种仅受理一次，第二种只接续原 Run。过期和绑定变化均报告结果不可用，历史保持原版本。已派发的原工具执行计数不增加 |
| C3 原子去重 | 分别在封存后、索引发布前退出，以及索引发布后、回执发出前退出。重启后并发提交，提交下一轮后再重试旧 `RunID` | 前一故障先读旧版本，再用封存记录提交。后一故障直接读新版本。同一增量只出现一次，均返回原回执。即使 B 原终态过期，已封存和已发布两条路径仍能完成对应操作 |
| C4 双会话 | 甲阻塞于慢工具。乙完成一轮并提交，再启动下一轮。甲仍阻塞时尝试给甲发不同 `RunID`，乙收到首段后取消甲 | 甲的第二次启动被拒且派发计数为零。乙后续流及提交继续，第二轮输入只含乙历史。甲的取消、事件和已确认消息只归甲，各会话版本按各自提交递增 |
| C5 提交保护 | 模拟跨会话或跨主体提交、同 ID 的终态内容冲突、新提交的旧版本和发布前的持久写入失败 | 分别报告归属、内容、版本或存储错误。前一个可读版本和原回执保持完整。原存储可用后，以原 `RunID` 重试只提交一次 |
