## Goals / Non-Goals

同一宿主完成组合故障验收，区分协议恢复通过与特定绑定的部署验收通过。适用边界见下方部署核对表。

## Decisions

复用独立进程、回环 mTLS、可控模型、共享所有权记录和原工具回执库。在实际持久边界设置屏障，读取接单记录和检查点确认故障位置。保留旧运行器存活的证据后再放行迟到操作。核对到期用原已保存的绝对期限判定。

```mermaid
flowchart LR
    A[旧运行器发送 c1] --> B[工具提交文件和证据]
    B --> C[工具在回执落盘前退出]
    C --> D[新运行器接管并按原身份查询]
    D -->|证据可信| E[提交 c1 结算]
    E --> F[再次退出并从检查点接续]
    F --> G[收齐批次或读取原终态]
    D -->|证据不足且到期或取消| H[ToolOutcomeUnknown]
```

| 用例 | 注入位置 | 通过依据 |
| --- | --- | --- |
| B1 · 接管并重建 | 工具发布后、回执落盘前退出。隔离仍存活的旧运行器，接管后重启原工具绑定 | 新所有权配合原接单代次查询。旧提交、派发和写入被拒。`c1` 传输、执行、发布和结算各一次。清理待确认时仍返回已知工具结果 |
| B2 · 再次崩溃 | 分别在可信回包后结算前、`c1` 已结算而 `c2` 未派发、批次提交后、终态提交后退出 | 首种可重复查询同一原调用。后三种分别从 `c2`、下一轮和原终态接续。已结算 `c1` 不再查询、派发或扣款。下一模型请求只含同序的两份配对结果 |
| B3 · 证据不足 | 在接管后分别撤掉原版本、返回错配证据或持续断开查询。分别用原期限和显式取消收尾，再恢复证据 | `ToolOutcomeUnknown` 关联原 `c1` 及停止原因，核对期限保持原值。后续派发和原调用重发为零。之后重启读取的终态、历史和账本一致 |
| B4 · 续跑门禁 | 可信重建回包已交付，在下一步派发前替换工作区。另测只够完成 `c1` 的原余额 | 保留一次 `c1` 结算。工作区分支沿用原不可用规则，预算分支按预算终止，两者均无后续派发 |
| B5 · 产物跨进程 | 使用部署选定的持久产物绑定，提交大于两页的产物后退出。分别注入原产物遗失、越权、篡改和过期 | 恢复后按原偏移分页核对整份内容和哈希。回执和检查点仅有引用。依赖失效时无后续派发和重发。只有测试夹具时，部署验收保持待完成 |
| B6 · 生命周期边界 | 终态保留期内外启动新进程。另用当前内置非保留产物或尚不支持恢复的压缩绑定启动 | 原终态在窗口内一致，窗口外不可查且无派发。能力不满足时受理拒绝，无检查点和派发 |

每项记录原调用键和查询键、所有权代次、原绝对期限、结算前后余额、模型与工具调用次数、可见文件版本，以及 `Wait` 的停止原因、历史与清理状态。只读查询可重复，原 `Invoke` 重发计数恒为零。

## 部署核对

| 后续范围 | 需要单独定下的验收 |
| --- | --- |
| 生产留存与物理回收 | 当前由宿主管理目录容量。确定回收和去重保留策略后，验证回收与在途查证并发时保住活跃记录、当前版本和未过期引用，且旧调用不能重新执行 |
| 多主机或沙箱 | 在目标环境验证跨节点所有权、时钟与存储可用性，覆盖网络分区和旧写入隔离。回环结果作为单机基线 |
| 可恢复压缩 | 确定视图、摘要账本和原文引用的持久化。验收重启后原约束、已用预算和来源可回查 |
| SDK 恢复后的观察 | 当前可用 `Recover` 和 `Wait` 读取持久状态。事件重放若纳入交付，再验收游标、保留窗口和断点去重 |

## Risks / Trade-offs

- 工具回包、结算和批次提交可能紧邻发生。每个用例先读取持久记录确认停点，再终止相应进程。
- 进程退出验收覆盖恢复协议和本机发布边界。实际部署使用的存储与执行环境各自提供能力验收。
