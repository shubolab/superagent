# Tasks

## 1. 持久受理和恢复入口

- [x] 1.1 接入本地检查点和单 Run 独占权。验证初始检查点提交前模型零调用、重复启动共用原记录、原进程仍持有推进权时恢复被拒。
- [x] 1.2 接入宿主的显式恢复、等待和取消。验证同主体并发恢复只推进一次、主体或绑定不符时零派发、首次等待超时后仍可读取终态，以及重启后重复返回已提交的终态。

## 2. 派发检查点和原回执核对

- [x] 2.1 在模型意图、完整模型回复、工具意图、单次结算和整批提交处持久推进。逐点注入退出并核对恢复位置、原消息顺序、预算和派发次数。
- [x] 2.2 让本地写入测试工具先登记再执行，持久保存回执后才回包。接通本地 Mesh 的只读查询，验证重复键只执行一次，指纹不匹配、无记录和明确未执行分别得到规定结果。
- [x] 2.3 接入有界核对、原期限和取消裁决。验证核对中重启不会延长期限、回执结算不重复、缺证据按预留结算、额度不足时零新派发。
- [x] 2.4 恢复后重新验证工作区和按次授权。验证工作区失效、旧写入未隔离或当前授权收紧时无越权副作用，并核对持久记录仅保留有界结果与可跨进程读取的稳定引用。

## 3. 双进程故障验收

- [x] 3.1 用确定的故障栅栏让进程 1 在持久保存原回执后、运行器结算前被强制终止。进程 2 以同一身份、工作区和 `RunID` 恢复。检查 `notes.txt` 仅一行 `saved:c1`、两进程合计只调用一次工具、查询键与原调用一致、下一轮模型只收到一份原结果、预算只结算一次，且重复 `Wait` 得到同一终态。
- [x] 3.2 用同一双进程夹具注入三个相邻断点。意图落盘但未交付时零执行并收尾为 `ToolOutcomeUnknown`；文件已写但原回执未保存时一次写入并收尾为 `ToolOutcomeUnknown`；整批已提交但下一轮意图未保存时零回执查询，直接进入下一轮且不重跑工具。核对三例的消息前缀与预算账本。
