## Why

进程可能在本地工具已经保存文件、运行器还未收到回执时退出。阶段 B 首步需要在同一台机器上查到原调用结果、接续原 Run，并验证整个过程中只发生一次文件写入。

## What Changes

- 宿主可显式开启持久化并用原 `RunID` 恢复。运行器在首次派发、工具批次提交和终态等关键边界保存检查点。
- 本地 Mesh 可查询原工具提供方的持久回执。运行器凭可信的原回执接续，查证窗口结束仍无法判定时提交 `ToolOutcomeUnknown`。
- 用可控模型、本地写文件测试工具和两次进程启动，验收回执丢失、重复恢复及检查点不同断点。

## Capabilities

### New Capabilities

- `run-recovery` 定义持久化 Run 在同一宿主重启后的检查点、原回执核对和恢复起点。

### Modified Capabilities

## Impact

涉及 Go SDK 的恢复入口、运行器的检查点与预算账本、本地 Mesh 的回执查询、测试工具的回执留存，以及同一工作区的续用。首步覆盖单机单进程所有权、本地工具和已保留工作区。
