# 阶段 C · 本地调度实现与验收清单

## 1. 装配与等待

- [x] 1.1 绑定宿主配置和本地调度器。验证非法容量与期限配置、同装配客户端共享名额，以及现有未启用调度的入口。
- [x] 1.2 实现有界 FIFO 和排队中的请求去重。验证零等待容量、排满、同会话忙、同 ID 异参，以及新请求无法抢在老请求之前。
- [x] 1.3 接入启动上下文与排队时限。验证主动取消、调用方截止和宿主等待到期分别可辨，重试者取消只影响自身，排队不计入 Run 执行时限。

## 2. 名额交接与恢复

- [x] 2.1 串接受理、停止推进和原子交接。用同步点验证取消与授予的两种顺序，验证明确拒绝、终止及重复通知只释放一次，受理不明时继续占用。
- [x] 2.2 给可派发的恢复和提交补跑接入同一门禁。验证原活跃 Run 复用名额、纯终态提交独立、直接入口无法越过受管容量，以及重启后的队列和检查点语义。

## 3. 集成验收

- [x] 3.1 用同一装配的两个客户端、两个会话和可控慢工具跑单名额用例。核对授予顺序、峰值、终态、会话版本和实际派发次数。
- [x] 3.2 跑完整矩阵、全量 Go 回归与 race 检查，记录各用例结果。

## 验收用例

核心场景配置活跃上限 1。两个会话使用独立客户端，共享同一个本地 Mesh 运行器。用同步点观察入队、派发和终止，截止时间用可控时钟推进。

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| 单名额交接 | 甲卡在慢工具，乙提交启动。甲终止后暂缓提交甲的历史 | 乙等待期间的会话预约、Run 检查点和派发均为 0。甲终止后乙自动流式输出并提交，甲仍可稍后提交。活跃峰值为 1 |
| 等待取消和超时 | 甲持续活跃。分别主动取消乙的启动上下文、触发调用方截止和宿主等待上限，再显式提交新的等待请求 | 乙得到对应结果，空出的位置可立即重用。甲继续运行。甲释放后原乙请求的派发仍为 0，乙原历史版本保持原值 |
| 排满、FIFO 和去重 | 甲占满。验证等待上限为 0、1、2，并以丙检验排满和次序。对乙重复提交原请求、同 ID 异参及不同 ID。取消一个重复等待者 | 排满立即拒绝。重复请求共享同一队项且期限不变，错误分别可辨。丙无法越过乙，重复等待者离开后乙仍按原序受理，乙的派发为 1 次 |
| 取消竞争 | 分别卡在乙获得名额前及授予后，让取消与释放竞争。获准分支分别模拟明确未受理和已受理 | 先取消时乙零派发。明确未受理时名额立即可交接。已受理时由原 Run 处理取消，确认终止前名额仍占用 |
| 异常与重复释放 | 模拟明确拒绝、受理不明、失败或取消终态及 `CleanupPending`。重放结束信号，关闭观察并让 `Wait` 超时 | 明确拒绝与可信终止各释放一次。受理不明时核对原 `RunID`。关闭观察和等待超时保持原占用。环境清理沿用环境自己的资源上限 |
| 恢复门禁 | 甲占满。分别提交已有终态、提交封存增量、恢复会重新推进的原 Run，并从直接入口尝试可派发调用 | 纯提交在满载时仍完成。需要推进的恢复等待名额，甲的原活跃恢复复用名额。未经门禁的派发为 0 |
| 进程重启 | 甲持有已落盘检查点，乙仍纯排队。结束原进程，启动同一宿主的新装配 | 等待队列为空。乙仅在宿主重送后可受理，甲经新装配名额从原 `RunID` 接续 |
