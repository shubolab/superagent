# TUI · 本地重进实现与验收清单

## 1. SDK 恢复边界

- [x] 1.1 提供只读待处理判定。用真实本地记录验证可信状态、绑定和请求摘要，以及检查时无写入和派发。
- [x] 1.2 接入只保存、只继续和清理未受理路径。验证原 ID 去重、封存补存、授予后的复核和已尝试但失去证据时的保留。

## 2. 终端重进与退出

- [x] 2.1 分别加载两条会话的已提交历史与恢复状态。验证单边读取或保存出错时，另一边可切换和发送。
- [x] 2.2 用当前会话的 `Enter` 继续原 Run，经原调度门禁并独立等待终态。验证原预算、原停止请求和重进前的观察流边界。
- [x] 2.3 实现有界主动退出。验证纯排队撤回、授予竞争和原 Run 恢复等待的不同结果，核对退出触发的 `Run.Cancel` 次数为零。

## 3. 验收

- [x] 3.1 用伪终端、独立子进程、同一真实本地状态目录和可控模型工具执行下表，记录每个会话的版本、原 `RunID`、接续步骤和实际派发次数。
- [x] 3.2 跑全量 Go 回归、race 检查与 OpenSpec 严格校验，记录各用例结果。

## 验收用例

进程一、进程二打开同一主体的甲、乙及原存储。主动退出用 `Ctrl+D`，故障边界用同步点强制结束进程。用真实 SDK 记录模型、工具、回执查询和历史提交，逐一核对终端显示。

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| 双会话历史 | 甲乙各提交不同内容，主动退出后重进，来回切换并各发送下一轮 | 重进时两条历史和版本与退出前一致。新请求分别得到自己的原历史和新输入，各一次 |
| 原 Run 接续 | 甲的原工具回执落盘后、结算前关闭进程。重进，先在乙操作，再在甲按 `Enter` 继续 | 甲打开时显示原 ID 和可继续，启动终端的新增派发为零。继续后查原回执，原工具执行总数为 1，按检查点推进，历史只提交一次。旧流的预览和事件无重放 |
| 终态补存 | 分别在 B 终态持久化、C 增量封存后且历史发布前关闭进程，再重进两次。封存分支令 B 终态过期 | 依原 ID 自动补存，历史只增一版，模型与工具新增派发为零。注入暂时保存失败时显示待保存，重试返回原回执 |
| 纯排队退出 | 单名额下甲活跃，乙纯排队。分别主动退出和强制关闭，再重进 | 乙新进程空闲，无原等待项、历史或 Run。乙旧请求派发始终为零，重新输入和发送后才产生新请求。甲仍可按原证据核对 |
| 授予与退出竞争 | 分别在乙仅有未尝试预约、已有初始检查点却未回复、已经尝试但原检查点不可查三个断点关闭进程 | 第一个清理原预约并恢复原草稿，发送前派发为零。第二个找回原 ID 并等待用户继续。第三个待核对并保留预约。三个分支均无自动补发 |
| 恢复门禁 | 分别保留旧进程推进权、替换或损坏原记录、令原终态过期，以及让可信未完成 Run 达到原截止或持有已受理的停止请求 | 占用或证据不足时保留原 ID 和历史，派发为零，乙仍可独立操作。可信过期执行或已停止分支按原期限和停止请求收尾 |
| 恢复等待再次退出 | 先准备两个已受理的未完成 Run。新进程以一个名额继续甲，乙申请继续后仍在等待，再退出并重进 | 第二次退出仅撤回恢复等待。第三个进程找回乙的原 ID、检查点和历史版本。用户再次确认前乙无新增派发 |
