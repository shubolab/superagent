# TUI · 本地重进契约

## ADDED Requirements

### Requirement: 重进后恢复双会话

终端 MUST 以原本地存储和会话身份分别读回已提交的历史版本，再核对各自的待处理 Run。一个会话的读回、核对或恢复 MUST 允许另一个会话独立切换和操作。

#### Scenario: 重新打开已保存的两条会话

- **WHEN** 用户退出后用相同宿主配置和两个 `SessionID` 重进，再来回切换
- **THEN** 甲乙分别显示自己的已提交历史，版本和消息次序一致
- **AND** 发送后续消息时，模型收到对应会话的已提交历史及本轮输入各一次

#### Scenario: 原终态尚待保存

- **WHEN** 原进程在可信终态或封存增量持久化后、会话发布前退出
- **THEN** 新终端按原 `RunID` 补存一次，显示确认后的历史。模型和工具派发均为零
- **AND** 保存暂时失败时显示「待保存」，用户可沿原 `RunID` 重试

### Requirement: 找回并继续原 Run

终端 MUST 为可信的未完成 Run 显示「可继续」及原 `RunID`。只有用户在该会话显式确认继续，终端才经本地调度申请继续该 Run。原结果或受理证据无法核对时 MUST 保留原标识和既有历史，显示「待核对」。

#### Scenario: 从可信检查点继续

- **WHEN** 甲有未完成的可信检查点，用户重进后切到甲并按 `Enter`
- **THEN** 继续原 `RunID`，遵守原检查点、预算、截止和已受理的停止请求
- **AND** 终端显示恢复状态和 `Wait` 结论，旧观察流无重放，乙可独立操作

#### Scenario: 原进程仍占用或证据不可用

- **WHEN** 原进程仍有推进权，或未完成 Run 的原记录缺失、损坏、过期或绑定不符
- **THEN** 甲显示对应的占用或待核对状态，保留原 `RunID` 和历史。自动和手动重发计数均为零
- **AND** 乙的历史、切换和启动不受影响

### Requirement: 退出与排队边界

主动退出 MUST 拒绝本进程的新操作并在有界时间内撤回尚在等待的请求。退出 MUST 保留已受理 Run 的持久记录，并沿用已有 `Esc` 停止语义。新进程 MUST 从空等待队列启动。

#### Scenario: 退出时乙仍是纯排队的新请求

- **WHEN** 甲占用唯一名额，乙仍在等待授予，用户主动退出或进程被强制关闭
- **THEN** 重进后乙没有排队请求、历史增量或原 Run。等待输入只在旧终端内有效
- **AND** 乙只有用户重新输入并发送后才申请名额

#### Scenario: 退出与乙受理相遇

- **WHEN** 退出前乙刚取得名额，但启动响应尚未交回终端
- **THEN** 新终端按原证据判断。可证未受理时清理预约并恢复已落盘的输入为草稿，有可信受理证据时保留原 Run，证据不足时显示待核对
- **AND** 退出本身不向任何已受理 Run 发出 `Run.Cancel`

#### Scenario: 退出时等待的是原 Run 的继续

- **WHEN** 已受理的原 Run 在当前终端等待继续名额，用户再次退出
- **THEN** 移除本次恢复等待，保留原检查点及原 `RunID`
- **AND** 下次重进时重新核对原 Run，用户可再次显式继续

## MODIFIED Requirements

### Requirement: 双会话切换与输入

终端 MUST 打开宿主指定的两个本地会话，同时显示各自状态和当前会话标记。`Tab` 切换当前会话，空闲可发送时 `Enter` 提交该会话的非空输入，有原 Run 待处理时按当前提示继续或保存。终端 MUST 按会话保留草稿和对话，且每个会话同一时刻只发起一个待完成的请求。

#### Scenario: 切换保留草稿

- **WHEN** 用户在甲输入草稿，切到乙输入并发送，再切回甲
- **THEN** 乙获得自己的输入，甲仍显示原草稿及自己的历史
- **AND** 连续按下 `Enter` 只为本次意图发起一次启动，另一个会话仍可切换或发送

### Requirement: 流式输出与终态

终端 MUST 为在当前终端发起并获得句柄的每个新 Run 建立一次独立观察，持续处理前后台事件。增量按原会话、`RunID` 和事件顺序显示。观察中断时 MUST 保持独立的 `Wait`。终态以 `Wait` 或 SDK 确认的原终态为准，以原 `RunID` 提交历史一次。

#### Scenario: 后台继续流式输出

- **WHEN** 甲、乙分别流式输出，用户读取甲后切到乙，再切回甲
- **THEN** 两个会话的输出分别累积，切回可见已收到的内容，切换不会重新建立 Run 观察
- **AND** 完整消息和终态替换对应预览，本次 Run 的确认增量只进入历史一次

#### Scenario: 观察中断或历史保存失败

- **WHEN** 某个 Run 的观察溢出或关闭，随后 `Wait` 返回可信终态
- **THEN** 先提示观察中断，收到终态后用完整结果收束预览，另一个会话继续更新
- **AND** 保存失败时显示待保存，原会话历史版本不变。按原 `RunID` 重试保存仍只追加一次
- **AND** 若 `Wait` 本身无法确认终态，则显示结果待核对并保留原 `RunID`
