# context-compaction-views Specification

## Purpose

定义可选的运行时上下文压缩，保护已提交的用户原文与工具配对，并规定摘要来源回查和压缩失败时的回退路径。

## Requirements

### Requirement: 按已提交原文构建模型视图

启用压缩的 Run MUST 在正式模型派发前评估软阈值、硬限额和输入字节，保护用户消息、宿主固定项、指令、工具定义、近期原文和完整工具批次。

#### Scenario: 边界及连续压缩
- **WHEN** 视图先低于，再达到软阈值，且随后提交了新轮次
- **THEN** 低于阈值的合规视图直接派发。多次压缩持续保留用户原文和顺序，按原始完整块关联摘要，原始提交和 Result.Messages 不变

### Requirement: 有界并可授权回查的来源

系统 MUST 将来源绑定到本 Run 的不可变消息块，提供稳定引用、按页读取和明确的越权或失效错误。只有获准的 Run 所有者或按次授权的来源工具能读取。

#### Scenario: 分页和隔离
- **WHEN** 回查同一 8 字节来源，并尝试跨 Run、跨主体和过期读取
- **THEN** 在 3 字节页上限下依次读到 3、3、2 字节，跨界访问不可查，视图更新不改变原文

### Requirement: 摘要预算与回退

运行器 MUST 为普通请求保留额度。同一提交版本至多摘要一次，摘要关工具，按实际资源入账。候选经完整性、来源、停止状态和新余额复核后才发布。

#### Scenario: 摘要失败和原文超限
- **WHEN** 摘要流中断、结构或引用不合法，或候选节省不足
- **THEN** 依次校验确定性缩减、补齐的先前视图及原始输入，派发首个合规视图；皆超限则以预算终态结束

#### Scenario: 主动取消和迟到候选
- **WHEN** 摘要在途且取消或 Run 截止生效
- **THEN** 不发布摘要或发起下一请求，沿用原停止原因及此前已提交的历史
