# run-recovery Specification

## Purpose

定义同一宿主进程重启后如何找回已受理的 Run、核对原工具回执，并在原预算与消息历史下从最近的安全边界继续或提交终态。

## Requirements

### Requirement: 持久化受理与恢复所有权

系统 MUST 显式受理可恢复 Run，在回应受理或派发任何工作前保存初始检查点。恢复 MUST 以原 `RunID`、可信主体和逻辑运行器定位记录，并在同一时刻只允许一个进程推进该 Run。

#### Scenario: 已保存初始检查点但受理响应丢失

- **WHEN** 进程在初始检查点持久化后、首个模型派发意图保存前退出，宿主以原身份恢复
- **THEN** 新进程取得同一 Run，从首个模型步骤开始，模型使用原输入、历史、绑定和额度
- **AND** 同身份重送原 `Start` 只返回原受理记录。相同标识配不同输入返回冲突

#### Scenario: 初始检查点不可保存

- **WHEN** 初始检查点保存失败且确认没有提交
- **THEN** 启动返回可识别的受理错误，模型和工具调用均为零

#### Scenario: 原进程仍持有推进权或恢复方不匹配

- **WHEN** 另一进程尝试恢复，但原进程仍持有所有权，或恢复主体、记录或绑定版本无法验证
- **THEN** 恢复返回可识别的错误，本次请求不派发模型或工具，也不改写原 Run
- **AND** 同一所有者并发重复恢复已接续的 Run 时，成功响应共用同一次推进

### Requirement: 检查点与恢复起点

运行器 MUST 在各次模型和工具派发前持久化意图及相关预算。有效的工具回复批次 MUST 先持久化，工具结果和该次结算 MUST 原子记录，完整工具批次 MUST 与下一步位置一并提交。恢复 MUST 按最后一个已提交状态推进。

#### Scenario: 模型流在完整回复提交前中断

- **WHEN** 模型派发意图已保存，进程在有效 `ModelCompleted` 对应的状态提交前退出
- **THEN** 恢复以 `Failed` 收尾并报告模型步骤中断，保留此前已提交的消息
- **AND** 当轮模型请求不补发，草稿不进历史，该轮工具调用为零

#### Scenario: 完整模型回复已保存且工具尚未记录意图

- **WHEN** 待执行批次已保存，进程在首个工具意图保存前退出
- **THEN** 恢复沿原调用顺序及 `CallID` 从派发前门禁接续，重新检查当前授权、工作区及剩余额度
- **AND** 通过检查后允许首次调用该工具，原模型步骤不补发

#### Scenario: 工具结果已结算或本轮已提交

- **WHEN** 进程在一个工具结果和账本提交后退出，或整批已提交而下一轮模型意图还未保存
- **THEN** 已结算结果直接从检查点使用，原工具的查询、执行及重复结算次数均为零
- **AND** 批次仍不完整时从首个未完成调用接续，整批已提交时从下一轮模型开始，配对结果仅在请求中出现一次

### Requirement: 原工具回执核对

运行器 MUST 将仅有派发意图的工具置于待核对，通过本地 Mesh 向原工具提供方查询。提供方 MUST 在产生效果前登记调用，先保存有界结论再返回。只有原主体、Run、步骤、调用标识、绑定、工作区及请求指纹匹配的回执可以结算。回执查询 MUST 只读，且不得再次派发该调用。

#### Scenario: 文件已保存且原回执已持久化

- **WHEN** 第一个进程执行 `c1` 并保存原回执，随后在运行器结算前退出，第二个进程用相同 `RunID` 恢复
- **THEN** 运行器向原提供方查询并采用 `c1` 的回执，该调用总共执行和结算各一次
- **AND** 文件只写一次。运行器提交助手声明和同序工具结果，下一轮模型只收到一份原结果

#### Scenario: 文件已写但原回执尚未保存

- **WHEN** 工作区已有文件修改，原提供方仅有未结案登记
- **THEN** 文件存在或内容吻合不构成结论，查证窗口内无新模型或工具派发
- **AND** 窗口结束仍无可信回执时，终态为关联 `c1` 的 `ToolOutcomeUnknown`，整批不进历史，文件写入仍为一次

#### Scenario: 派发意图已记录但提供方没有记录

- **WHEN** 进程在派发意图持久化后、交付前退出，查询得到无记录
- **THEN** 无记录保留为待核对，实际工具执行次数仍为零
- **AND** 查证截止后提交 `ToolOutcomeUnknown`，同一调用不重新派发

#### Scenario: 回执身份不符

- **WHEN** 提供方返回标识或指纹不匹配的回执
- **THEN** 该回执不计入结算，继续按待核对处理

#### Scenario: 回执确认原调用未执行

- **WHEN** 提供方返回匹配的明确未执行回执，并确认原尝试已无法再产生效果
- **THEN** 运行器按配对失败结果结算。Run 仍可继续时，结果随完整批次交给模型

### Requirement: 原额度和有限核对窗口

恢复 MUST 保留原截止时间、预算账本和已受理的停止请求。核对上限 MUST 取原 Run 截止时间与首次持久化的核对期限中较早者。超时或显式取消生效时，未判定的原调用 MUST 以 `ToolOutcomeUnknown` 收尾，且记录触发停止的原因。

#### Scenario: 核对期间再次退出

- **WHEN** 新进程已保存核对期限，回执始终不可用，进程在核对期间再次退出
- **THEN** 后续恢复沿用已保存的期限及账本，期限届满后 `Wait` 返回与原调用关联的 `ToolOutcomeUnknown`
- **AND** 核对请求不消耗新一轮工具尝试，无法核实的原步骤用量按原已留额度结算

#### Scenario: 核对等待被取消

- **WHEN** 一个 `Wait` 调用超时，随后宿主显式取消仍有未判定调用的 Run
- **THEN** 前者只结束本次等待。显式取消持久化并结束核对，`Wait` 返回 `ToolOutcomeUnknown` 及取消原因，后续派发为零

#### Scenario: 预算耗尽或停止已生效

- **WHEN** 回执已结算且继续需要的额度不足，或恢复时已存在生效的截止或显式取消且无未判定调用
- **THEN** 按原预算或停止原因收尾，不发起新模型或工具请求

### Requirement: 稳定终态与有界留存

系统 MUST 在终态可见前保存同一份结果，保留期内重复恢复或 `Wait` 返回同一终态。检查点和回执 MUST 只保留续跑所需的有界数据及稳定引用，恢复前核验后续步骤仍可使用所需工作区。

#### Scenario: 终态提交后进程退出

- **WHEN** 终态持久化后、首次 `Wait` 返回前进程退出
- **THEN** 重复恢复和等待取得相同结果，模型、工具派发和回执查询次数均为零

#### Scenario: 工作区不可续用

- **WHEN** 所需工作区不可用或旧写入仍未隔离，但原工具有有效回执
- **THEN** 已知回执保留，依赖工作区的后续调用停止派发
- **AND** 原 Run 截止先到时返回 `TimedOut`，核对窗口先到时返回工作区不可用的 `Failed`

#### Scenario: 工具返回大产物引用

- **WHEN** 有效工具回执引用需跨进程读取的大产物
- **THEN** 大产物仍由原保留位置持有。检查点仅保存有界结果与稳定引用，跨进程读取得到同版本产物
