# run-recovery Specification

## Purpose

定义同一宿主进程重启后如何找回已受理的 Run、核对原工具回执，并在原预算与消息历史下从最近的安全边界继续或提交终态。

## Requirements

### Requirement: 持久化受理与恢复所有权

系统 MUST 显式受理可恢复 Run，在回应受理或派发任何工作前保存初始检查点。恢复 MUST 以原 `RunID`、可信主体和逻辑运行器定位记录，并在同一时刻只允许一个进程推进该 Run。

#### Scenario: 已保存初始检查点但受理响应丢失

- **WHEN** 进程在初始检查点持久化后、首个模型派发意图保存前退出，宿主以原身份恢复
- **THEN** 新进程取得同一 Run，从首个模型步骤开始，模型使用原输入、历史、绑定和额度
- **AND** 同身份重送原 `Start` 只返回原受理记录。相同标识配不同输入返回冲突

#### Scenario: 初始检查点不可保存

- **WHEN** 初始检查点保存失败且确认没有提交
- **THEN** 启动返回可识别的受理错误，模型和工具调用均为零

#### Scenario: 原进程仍持有推进权或恢复方不匹配

- **WHEN** 另一进程尝试恢复，但原进程仍持有所有权，或恢复主体、记录或绑定版本无法验证
- **THEN** 恢复返回可识别的错误，本次请求不派发模型或工具，也不改写原 Run
- **AND** 同一所有者并发重复恢复已接续的 Run 时，成功响应共用同一次推进

### Requirement: 检查点与恢复起点

运行器 MUST 在各次模型和工具派发前持久化意图及相关预算。有效的工具回复批次 MUST 先持久化，工具结果和该次结算 MUST 原子记录，完整工具批次 MUST 与下一步位置一并提交。恢复 MUST 按最后一个已提交状态推进。

#### Scenario: 模型流在完整回复提交前中断

- **WHEN** 模型派发意图已保存，进程在有效 `ModelCompleted` 对应的状态提交前退出
- **THEN** 恢复以 `Failed` 收尾并报告模型步骤中断，保留此前已提交的消息
- **AND** 当轮模型请求不补发，草稿不进历史，该轮工具调用为零

#### Scenario: 完整模型回复已保存且工具尚未记录意图

- **WHEN** 待执行批次已保存，进程在首个工具意图保存前退出
- **THEN** 恢复沿原调用顺序及 `CallID` 从派发前门禁接续，重新检查当前授权、工作区及剩余额度
- **AND** 通过检查后允许首次调用该工具，原模型步骤不补发

#### Scenario: 工具结果已结算或本轮已提交

- **WHEN** 进程在一个工具结果和账本提交后退出，或整批已提交而下一轮模型意图还未保存
- **THEN** 已结算结果直接从检查点使用，原工具的查询、执行及重复结算次数均为零
- **AND** 批次仍不完整时从首个未完成调用接续，整批已提交时从下一轮模型开始，配对结果仅在请求中出现一次

### Requirement: 原工具回执核对

运行器 MUST 将仅有派发意图的工具置于待核对，通过本地 Mesh 向原工具提供方查询。提供方 MUST 在产生效果前登记调用，先保存有界结论再返回。只有原主体、Run、步骤、调用标识、绑定、工作区及请求指纹匹配的回执可以结算。回执查询 MUST 只读，且不得再次派发该调用。

#### Scenario: 文件已保存且原回执已持久化

- **WHEN** 第一个进程执行 `c1` 并保存原回执，随后在运行器结算前退出，第二个进程用相同 `RunID` 恢复
- **THEN** 运行器向原提供方查询并采用 `c1` 的回执，该调用总共执行和结算各一次
- **AND** 文件只写一次。运行器提交助手声明和同序工具结果，下一轮模型只收到一份原结果

#### Scenario: 文件已写但原回执尚未保存

- **WHEN** 工作区已有文件修改，原提供方仅有未结案登记
- **THEN** 文件存在或内容吻合不构成结论，查证窗口内无新模型或工具派发
- **AND** 窗口结束仍无可信回执时，终态为关联 `c1` 的 `ToolOutcomeUnknown`，整批不进历史，文件写入仍为一次

#### Scenario: 派发意图已记录但提供方没有记录

- **WHEN** 进程在派发意图持久化后、交付前退出，查询得到无记录
- **THEN** 无记录保留为待核对，实际工具执行次数仍为零
- **AND** 查证截止后提交 `ToolOutcomeUnknown`，同一调用不重新派发

#### Scenario: 回执身份不符

- **WHEN** 提供方返回标识或指纹不匹配的回执
- **THEN** 该回执不计入结算，继续按待核对处理

#### Scenario: 回执确认原调用未执行

- **WHEN** 提供方返回匹配的明确未执行回执，并确认原尝试已无法再产生效果
- **THEN** 运行器按配对失败结果结算。Run 仍可继续时，结果随完整批次交给模型

### Requirement: 原额度和有限核对窗口

恢复 MUST 保留原截止时间、预算账本和已受理的停止请求。核对上限 MUST 取原 Run 截止时间与首次持久化的核对期限中较早者。超时或显式取消生效时，未判定的原调用 MUST 以 `ToolOutcomeUnknown` 收尾，且记录触发停止的原因。

#### Scenario: 核对期间再次退出

- **WHEN** 新进程已保存核对期限，回执始终不可用，进程在核对期间再次退出
- **THEN** 后续恢复沿用已保存的期限及账本，期限届满后 `Wait` 返回与原调用关联的 `ToolOutcomeUnknown`
- **AND** 核对请求不消耗新一轮工具尝试，无法核实的原步骤用量按原已留额度结算

#### Scenario: 核对等待被取消

- **WHEN** 一个 `Wait` 调用超时，随后宿主显式取消仍有未判定调用的 Run
- **THEN** 前者只结束本次等待。显式取消持久化并结束核对，`Wait` 返回 `ToolOutcomeUnknown` 及取消原因，后续派发为零

#### Scenario: 预算耗尽或停止已生效

- **WHEN** 回执已结算且继续需要的额度不足，或恢复时已存在生效的截止或显式取消且无未判定调用
- **THEN** 按原预算或停止原因收尾，不发起新模型或工具请求

### Requirement: 稳定终态与有界留存

系统 MUST 在终态可见前保存同一份结果，保留期内重复恢复或 `Wait` 返回同一终态。检查点和回执 MUST 只保留续跑所需的有界数据及稳定引用，恢复前核验后续步骤仍可使用所需工作区。

#### Scenario: 终态提交后进程退出

- **WHEN** 终态持久化后、首次 `Wait` 返回前进程退出
- **THEN** 重复恢复和等待取得相同结果，模型、工具派发和回执查询次数均为零

#### Scenario: 工作区不可续用

- **WHEN** 所需工作区不可用或旧写入仍未隔离，但原工具有有效回执
- **THEN** 已知回执保留，依赖工作区的后续调用停止派发
- **AND** 原 Run 截止先到时返回 `TimedOut`，核对窗口先到时返回工作区不可用的 `Failed`

#### Scenario: 工具返回大产物引用

- **WHEN** 有效工具回执引用需跨进程读取的大产物
- **THEN** 大产物仍由原保留位置持有。检查点仅保存有界结果与稳定引用，跨进程读取得到同版本产物

### Requirement: 共享租约裁决接管

对显式启用接管的 Run，系统 MUST 由共享权威按逻辑运行器、可信主体和原 `RunID` 裁决推进权。权威使用自身时钟确定租约到期，原租约失效后以单次原子操作授予一个获准的新实例，并分配严格递增的所有权代次。续租 MUST 匹配当前实例及未到期的代次。

#### Scenario: 失联时原租约仍有效

- **WHEN** 旧运行器失联但租约仍有效，宿主请求接管
- **THEN** 候选运行器报告原 Run 仍被占用，检查点、新模型请求和新工具请求均无变化

#### Scenario: 两个候选竞争已到期的租约

- **WHEN** 原租约到期，两个候选使用同一检查点并发申请接管
- **THEN** 只有一个取得下一代次并获准恢复，另一个不推进
- **AND** 新代次沿用原 Run 标识和绑定。跨主体或绑定版本不符的申请不改变所有权

#### Scenario: 旧运行器迟到续租

- **WHEN** 租约已到期，旧进程仍存活并补发续租
- **THEN** 续租被拒。已过期的代次无法重新生效，即使新运行器尚未接管

### Requirement: 失效代次的状态提交与派发准入

检查点、账本、消息、取消和终态的提交 MUST 在同一次条件写入中验证当前持有实例、代次、租约有效期与预期检查点修订号。新的模型或工具接单及环境授权 MUST 与所有权变更按同一权威排序，核对持有实例、有效代次与已持久化的原意图。无法确认时 MUST 停止新的提交与派发。

#### Scenario: 旧进程使用最新修订号提交

- **WHEN** 新运行器已取得推进权，旧进程提交迟到的模型结果、预算结算、消息批次、取消或终态，并带上当前修订号
- **THEN** 这些请求均被拒，旧进程不得发布该提交对应的成功或终态
- **AND** 共享状态只保留当前持有者提交的内容

#### Scenario: 旧派发在接管后到达

- **WHEN** 旧运行器在接管前发出的模型请求、工具请求或环境授权请求排队到接管后才到达准入点
- **THEN** 组件拒绝接单或授权，模型和工具新增执行均为零

#### Scenario: 权威不可达或租约已过期

- **WHEN** 任一运行器无法从权威确认所有权，或提交抵达时租约已经到期且尚无人接管
- **THEN** 没有新的状态提交、模型或工具接单、环境授权或工作区发布
- **AND** 已受理的取消与已提交的终态仍以共享记录为准

### Requirement: 在途旧写入与工作区隔离

可接管的工作区 MUST 由执行环境控制可见写入点，使写入的发布与所有权变更有确定的先后顺序。旧代次失效后，已获准的旧调用也不得写入保留工作区或发布可见产物。新运行器 MUST 在依赖该工作区的推进前取得环境确认，证明旧写入已被隔离且仍是原工作区。

#### Scenario: 旧工具已接单但仍在发布前

- **WHEN** 旧工具持有旧授予的能力，在写入对工作区可见前停住，随后新运行器接管
- **THEN** 旧调用恢复执行时无法发布原工作区修改或可见产物
- **AND** 旧能力不能释放新代次的环境句柄。旧调用清理与写入结局可分别确认

#### Scenario: 无法确认工作区隔离

- **WHEN** 原工具已有可信结果，但执行环境无法确认旧写入已隔离或原工作区仍可使用
- **THEN** 当前运行器保留原回执，依赖该工作区的后续派发为零，并沿用原期限按工作区不可用或到期收尾
- **AND** 接管模式拒绝使用能够绕过发布边界的工作区能力

### Requirement: 跨代次的原工具回执

工具提供方 MUST 将回执与原次接单记录绑定并持久保存。当前运行器 MUST 经 Mesh 只读查询原提供方，核对原 Run、调用标识、接单代次、绑定、工作区及请求指纹，并在持有当前有效代次时将回执和原次数结算一次。旧运行器转发的迟到响应只能用作诊断。同一原调用 MUST 保持原 `CallID` 且不得重发。

#### Scenario: 写入发生在接管前而回执在接管后可查

- **WHEN** 原工具已经发布文件修改，旧运行器失联未结算，原提供方在接管后保存可验证的原回执
- **THEN** 新运行器使用原接单代次查询并采用该回执，继续原 Run
- **AND** 原工具执行、文件写入、预算结算及模型收到的原结果各为一次

#### Scenario: 迟到响应来自旧运行器或回执身份不符

- **WHEN** 旧运行器先转发成功响应，或者原查询收到接单代次、提供方、请求指纹或工作区不匹配的回执
- **THEN** 该响应不能结算或进入消息，同一调用仍待核对

#### Scenario: 可信回执重复交付

- **WHEN** 原回执被重复查询，或结算提交响应丢失后再次恢复
- **THEN** 已提交结算、配对消息和下一轮位置保持各一份，不重复扣预算或重发原调用

#### Scenario: 旧写入确定未发生

- **WHEN** 原提供方能证明原调用从未发布效果且原发布已被永久阻断，并保存匹配的明确未执行回执
- **THEN** 当前运行器可以提交与原 `CallID` 配对的失败结果
- **AND** 整个工具批次就绪后，模型可以提出使用新 `CallID` 的调用，并重新经过门禁

### Requirement: 接管沿用原运行边界

当前运行器 MUST 从共享记录的最后已提交边界恢复，沿用原截止、已持久化的核对期限、停止请求和预算。待核对期间 MUST 暂停新的模型与工具派发。未知结果在截止或取消时 MUST 以关联原调用的 `ToolOutcomeUnknown` 收尾，已提交终态 MUST 保持固定。

#### Scenario: 已完成的工具批次已经提交

- **WHEN** 旧运行器已经提交完整工具批次与下一轮位置，但还未获准派发下一轮模型
- **THEN** 新运行器从下一轮开始，旧工具回执查询和重发为零，完整配对结果只交给模型一次

#### Scenario: 核对到期后收到有效回执

- **WHEN** 核对截止仍查不到可信回执，当前运行器已提交 `ToolOutcomeUnknown`，随后原回执变得可查
- **THEN** 原终态、预算和消息保持不变，迟到回执只留在工具侧记录或诊断，后续模型和工具派发为零

#### Scenario: 核对期间再次接管

- **WHEN** 当前运行器已保存核对期限，随后自己的租约也到期，另一获准运行器接管
- **THEN** 新运行器沿用原核对期限和余额，原调用不补发，旧运行器的查询结果不能提交

### Requirement: 远程工具意图与原提供方回执

可恢复 Run 在首次发送远程 `Invoke` 前 MUST 保存工具意图、原调用身份、提供方与回执库身份、绑定版本、请求指纹、工作区身份及预算预留。提供方 MUST 在产生副作用前持久登记原调用，在原 `Invoke` 回复已知结果前持久保存可查询的有界回执。缺少已完成回执时，`QueryReceipt` 按写入证据重建要求裁决。

#### Scenario: 派发意图保存失败

- **WHEN** 运行器无法确认原调用意图和预算已提交
- **THEN** 远程 `Invoke` 发送次数与文件写入次数均为零

#### Scenario: 原请求重复到达提供方

- **WHEN** 提供方收到相同原调用的重复交付，或相同调用标识携带不同请求指纹
- **THEN** 前者只返回已登记状态，后者被拒为冲突，两者均不产生额外执行

#### Scenario: 文件已保存后响应连接关闭

- **WHEN** 原工具已确认文件保存，连接在回包前关闭
- **THEN** 已知结果仍按原调用存入回执库，后续可经新连接查询
- **AND** 回执固化有独立的有界完成时间，响应连接取消不能撤销已完成的写入或已保存的回执

### Requirement: 远程断连进入原调用待核对

Mesh MUST 区分有确证的未交付与可能已交付。可恢复 Run 对后者 MUST 暂停新的模型及工具派发，从原未结算调用进入待核对。Mesh 自动重试、重连及重定向 MUST NOT 再发原 `Invoke`。

#### Scenario: 回包途中断连

- **WHEN** 原请求可能已送达，调用以 EOF、超时、连接关闭或不完整响应结束
- **THEN** 运行器沿用同一 `RunID`、`CallID`、检查点与预算进入待核对
- **AND** 连接重建期间只有回执查询可以重试，原 `Invoke` 重发和后续模型派发均为零

#### Scenario: 能确证请求从未交付

- **WHEN** Mesh 证实原请求从未进入传输，且原尝试无法在稍后送达
- **THEN** 运行器可提交原 `CallID` 对应的明确未执行结果，原工具查询和执行均为零

### Requirement: 重连后查询原回执

Mesh MUST 经受信连接向原提供方的原回执库发送只读 `QueryReceipt`。每次查询有独立传输请求标识，原调用标识保持固定。只有与原主体、Run、步骤、调用、接单代次（如启用）、提供方、绑定和回执库、工作区及请求指纹匹配，且满足原回执字节上限的结果才可进入结算。

#### Scenario: 重新连接原提供方

- **WHEN** 原连接丢失，原绑定可通过新连接重新访问同一回执库
- **THEN** 查询仍命中原提供方与回执库，原调用标识保持不变，查询使用新的传输请求标识
- **AND** 查询权限仅允许读取原回执，无工具派发、工作区写入及重新授权

#### Scenario: 收到来自其他提供方或不匹配的回执

- **WHEN** 地址改指另一提供方，或返回的回执身份、工作区、接单代次或指纹不符
- **THEN** Mesh 或运行器拒绝该回执，不结算或发起后续模型请求，也不改查默认绑定

#### Scenario: 回执查询中断或收到非法响应

- **WHEN** 查询连接再次中断，或响应不完整、超限、不可鉴别或权限被拒
- **THEN** 运行器保持待核对，在原绝对期限内只读重试，拒绝累积超限字节或应用部分回执

#### Scenario: 回执库报告待完成或无记录

- **WHEN** 同一回执库报告待完成或无记录
- **THEN** 调用保持待核对。文件存在、内容匹配或连接中断均不能证明原调用结局

#### Scenario: 原提供方证明明确未执行

- **WHEN** 匹配的原回执证明原尝试未产生效果且已阻止后续执行
- **THEN** 运行器按原 `CallID` 提交配对失败并结算一次，原 `Invoke` 重发为零

### Requirement: 从原检查点接续远程工具批次

当前拥有推进权的运行器 MUST 从最后已提交的检查点接续。可信原回执、该调用结算及完成位置 MUST 原子写入。只有整批配对结果就绪并提交后才能进入下一轮。继续依赖原工作区时 MUST 核实原环境可用及必要的旧写入隔离。

#### Scenario: 保存成功后丢失回包，查询返回原结果

- **WHEN** 远程工具已在原工作区写入一次且回执已持久化，Mesh 丢失该次回包
- **THEN** 运行器查询并结算原 `c1` 一次，按原顺序提交助手声明及工具结果，下一轮模型只收到一份配对结果
- **AND** 原 `Invoke` 总发送、提供方执行和文件写入各一次

#### Scenario: 结算完成后连接重复返回或运行器重启

- **WHEN** 原回执重复交付，或运行器恢复时该工具已结算或整批已提交
- **THEN** 已结算结果直接从检查点使用。批次未齐则从首个未完成调用接续，批次已提交则进入下一轮
- **AND** 已结算的原调用不再查询、派发或扣减预算

#### Scenario: 回执可信但原工作区不可续用

- **WHEN** 取得匹配原回执，但依赖的工作区无法核验或必要写入隔离未确认
- **THEN** 保留已确认结果，依赖该工作区的后续派发为零，按照原工作区不可用或到期规则收尾

### Requirement: 远程回执缺失时有界收尾

运行器 MUST 在首次待核对时持久保存绝对核对期限，取配置窗口和原 Run 截止中较早者。重连、重启和接管 MUST NOT 延长期限。截止或显式取消时仍无可信回执，MUST 以关联原调用的 `ToolOutcomeUnknown` 提交终态。清理状态 MUST 与工具结局独立。

#### Scenario: 文件已保存但原回执缺失

- **WHEN** 远程工具已经写入，但在持久保存回执前失败，或网络在整个核对窗口持续不可达
- **AND** 原核对期限结束时，仍无可信的持久回执或按原写入证据重建的回执
- **THEN** 原 `Wait` 返回 `ToolOutcomeUnknown` 和原调用及停止原因。未完成工具批次不进入历史，已有提交保持不变
- **AND** 后续模型派发和原 `Invoke` 重发为零。无法确认清理时单独记录待确认

#### Scenario: 核对期间重启、接管或取消

- **WHEN** 同一 Run 在核对期间重启或接管，或宿主显式取消原 Run
- **THEN** 当前推进者沿用原预算、截止和已保存的核对期限。显式取消在效果仍不明时以原调用的 `ToolOutcomeUnknown` 收尾
- **AND** 单次 `Wait` 超时或连接关闭只结束本次等待

#### Scenario: 终态提交后收到原回执

- **WHEN** 已提交终态，原提供方随后才返回有效回执
- **THEN** 该回执保留在提供方记录或诊断中，重复 `Wait` 得到同一终态，消息、结算及后续派发保持不变

### Requirement: 写入可见版本与原调用证据共同提交

声明写工作区的远程工具 MUST 使用 `EvidenceWorkspace`，并在派发前固定结果重建规则版本。提供方 MUST 在装配时拒绝缺少任一条件的写入绑定。执行环境 MUST 在同一持久发布边界提交文件的可见版本与已提交证据。证据 MUST 绑定原主体、逻辑运行器、Run、步骤、`CallID`、原接单代次、工具和提供方绑定、请求指纹、环境与工作区身份、规范路径、写入内容摘要及结果版本。有接管时，发布 MUST 与所有权变更保持原有顺序约束。

#### Scenario: 文件已暂存但尚未发布

- **WHEN** 工具或环境在新版本数据暂存完成后、发布提交前退出
- **THEN** 通过托管路径只能看到先前版本或文件不存在，按原 `CallID` 查不到已提交的写入证据

#### Scenario: 发布已提交但尚未确认

- **WHEN** 执行环境已持久提交发布，进程在返回发布确认前退出
- **THEN** 重新打开原工作区后可以读取对应的新版本，并查到同一提交产生的原调用证据

#### Scenario: 原调用重复申请发布

- **WHEN** 同一原调用提交相同发布请求，或尝试以该调用标识发布不同路径或内容
- **THEN** 相同请求只能引用已提交版本，冲突请求被拒，文件无额外写入

#### Scenario: 旧代次在接管后尝试发布

- **WHEN** 旧工具已暂存数据但未提交，随后原所有权失效并发生接管
- **THEN** 旧代次不能发布可见版本或已提交证据。接管只核对接管前已获准提交的原调用证据

### Requirement: 原写入证据的认证查询和保留

执行环境 MUST 在原工作区的受信边界提供只读证据查询，核验查询方权限与原调用绑定。已发布版本和证据 MUST 按接单时固定的期限留存，至少覆盖原 Run 核对及约定去重窗口。证据记录 MUST 有界，并引用已留存的不可变文件版本。

#### Scenario: 同一路径随后发布了新版本

- **WHEN** 原 `c1` 的写入已经提交，随后获准的另一次调用更新同一逻辑路径
- **THEN** 按 `c1` 查询仍返回第一次发布的版本、摘要及长度，重建使用原版本的数据

#### Scenario: 原工具释放调用资源

- **WHEN** 原工具调用句柄已撤销，或提供方和环境进程在留存期内重启
- **THEN** 获准的原提供方仍可只读核验原证据及所引用版本，查询和重试不延长留存期

#### Scenario: 无权或无法匹配原环境的查询

- **WHEN** 查询主体、原环境绑定或工作区身份不符
- **THEN** 查询被拒，不交付其他主体、其他工作区或当前同名文件的证据

### Requirement: 原工具提供方按证据重建回执

原工具提供方 MUST 优先返回有效的持久原回执。原接单记录匹配且没有已完成回执时，才可只读核验原环境证据。只有证据唯一且已提交、原版本可核实、请求及写入匹配、预先固定的规则能还原全部必要结果且符合原字节上限时，才可返回重建的已知成功回执。查询 MUST 保持只读。

#### Scenario: 远程文件已发布而原回执未落盘

- **WHEN** 远程工具完成原 `c1` 的单次托管写入后、保存原回执前退出，重启后的原提供方查到匹配证据
- **THEN** `QueryReceipt` 返回与正常成功路径相同的业务结局和有界必要结果，并关联原证据
- **AND** 当前运行器只提交一次原结果和预算结算，整批提交后从下一轮继续，原 `Invoke` 和文件写入仍各一次

#### Scenario: 已有匹配的正常回执

- **WHEN** 原提供方已有可信的持久回执
- **THEN** 查询直接返回该回执，环境证据查询和新执行次数均为零

#### Scenario: 证据与原接单信息不符或有冲突

- **WHEN** 证据的调用身份、接单代次、指纹、目标路径、写入内容或持久版本不匹配，或发现证据冲突
- **THEN** 保持待核对，禁止使用该证据生成结果或结算

#### Scenario: 写入不能证明整个工具结果

- **WHEN** 未固定重建规则，规则版本已无法使用，原调用还有未证明的效果、所需结果字段缺失，或重建结果超过原回执上限
- **THEN** 提供方保持结果不可确认，运行器不提交该工具结果

### Requirement: 写入证据不足时保持既定收尾

证据缺失、过期、不可读取或无法核验时，运行器 MUST 沿用首次持久化的绝对核对期限和原停止规则。到期或显式取消仍无可信结论时，MUST 以原 `CallID` 提交 `ToolOutcomeUnknown`。未完成批次 MUST 保持未提交，原调用不得重发。环境清理状态 MUST 独立回报。

#### Scenario: 文件内容吻合但没有原证据

- **WHEN** 工作区路径存在，甚至内容哈希吻合，但没有可信证据关联原调用和原提交
- **THEN** 查证截止后以 `ToolOutcomeUnknown` 收尾，不推断成功或明确未执行，后续模型和原工具重发均为零

#### Scenario: 证据存在但原版本不可核验

- **WHEN** 原版本已丢失、留存期已过、证据未通过校验或原环境持续不可达，且核对截止或显式取消先发生
- **THEN** 提交关联原调用和停止原因的 `ToolOutcomeUnknown`，保留已提交的消息前缀
- **AND** 不能核实的用量沿用原预算预留，释放未知单独记为待确认

#### Scenario: 终态之后证据才恢复可查

- **WHEN** Run 已因证据不足提交终态，随后出现可信证据
- **THEN** 原终态与预算、历史保持固定，证据仅留存或用于诊断，重复 `Wait` 返回同一结果

### Requirement: 按原回执恢复本地产物发布和结算

使用本地持久产物绑定的可恢复 Run MUST 固定原存储身份。收到含产物引用的可信回执后，当前运行器 MUST 核验原调用、封存元数据、完整正文和原预算，再接用或发布同一版本。工具结果、引用和扣减 MUST 一次提交。恢复沿用原绝对核对期限，且不得重发原工具。

#### Scenario: 原回执已落盘而正式发布尚未提交

- **WHEN** 写入进程封存产物并保存匹配回执，在产物变为可见前退出
- **THEN** 新运行器在原核对窗口内核验完整正文，发布同一引用，按已确认的实际原始输出和有界回执各结算一次
- **AND** 产物正文保留在原绑定中，模型和检查点只接收配对结果与引用

#### Scenario: 正式发布后但运行器结算前退出

- **WHEN** 产物已持久发布，运行器在工具结果与账本提交前退出或丢失确认
- **THEN** 后继使用同一已发布版本完成原结算，保留原到期时间。工具执行、可见发布及最终结算各一次

#### Scenario: 新代次接管时原产物已封存

- **WHEN** 当前所有者取得原接单代次对应的可信回执，旧运行器仍存活
- **THEN** 当前所有者只能确认原调用已持久封存的同一版本。旧进程的封存和发布提交被拒，原调用的派发与写入均不重复

### Requirement: 本地产物不可用时保护原工具事实

系统 MUST 区分待核对调用、已结算结果及已提交终态。未核验的产物不得进入待提交的工具批次。恢复继续依赖已结算产物时 MUST 先核验所需引用，匹配失败或超过原窗口即停止相关推进。产物失败不得触发原调用重发。

#### Scenario: 待核对的原结果缺少可用产物

- **WHEN** 原回执缺失，或其中的产物缺失、损坏、不匹配或已过期，且原核对期限到期或显式取消先发生
- **THEN** 按原 `CallID` 返回 `ToolOutcomeUnknown`，未完整批次不进入历史。无法核实的用量按原预留结算，继续派发和原调用重发均为零

#### Scenario: 已结算且续跑仍需使用的产物不可用

- **WHEN** 后继运行器从部分工具批次或下一轮模型意图前的检查点接续，且这一步依赖的已结算产物无法验证
- **THEN** 保留已提交的工具结算和历史，按产物不可用结束 `Failed`，原取消或 Run 截止已生效时沿用对应停止原因
- **AND** 不再次扣减该调用，也不派发依赖它的下一步

#### Scenario: 终态提交后产物遗失或过期

- **WHEN** Run 终态已提交，有效引用对应的产物随后遗失、损坏或过期
- **THEN** `ReadArtifact` 报告产物不可用，`Wait` 在结果保留期内继续返回原终态及原引用

### Requirement: 接管后按原写入证据恢复

原工具进程在文件发布后、回执持久化前退出时，接管后的当前运行器 MUST 经受信连接按原接单代次和原调用身份查证。只有当前所有者可以提交重建结果。结算 MUST 绑定原调用、原证据和原预算。文件效果与清理状态 MUST 分别裁决。

#### Scenario: 新代次重建已发布写入的回执

- **WHEN** 原工具已提交文件及 `c1` 证据，随后在保存回执前退出，旧运行器仍存活，新运行器在原期限内接管并查到可信证据
- **THEN** 查询携带当前所有权及原接单身份，当前所有者仅提交一次 `c1` 结果与结算，原 `Invoke` 和文件发布各一次
- **AND** 旧运行器的迟到提交和派发均被拒绝。若清理未获确认，已知结果和清理待确认分别报告

#### Scenario: 接管后仍无法核实原写入

- **WHEN** 新运行器接管后原证据缺失、版本不可验证或查询持续不可达，直到原期限结束或显式取消生效
- **THEN** 按原 `c1` 和实际停止原因提交 `ToolOutcomeUnknown`，未完成批次不进入历史，保留之前已提交的消息，并按原预留结算无法核实的用量
- **AND** 原 `Invoke` 重发和后续派发均为零。终态后的有效证据不改写结果、历史或账本

### Requirement: 重建结算后的批次恢复位置

重建回执的结果、证据引用、预算扣减和已完成位置 MUST 同时提交。再次恢复 MUST 区分尚未结算、批次部分结算、批次已提交和终态已提交，并从对应位置接续。

#### Scenario: 重建结果已返回但尚无可靠结算

- **WHEN** 运行器已收到 `c1` 重建回执，在确认结算持久化前退出，且后继运行器读取到的记录仍待核对
- **THEN** 后继可重复查询原调用，在原期限内按可信结果结算一次，原 `Invoke` 仍只发送一次

#### Scenario: 第一项已结算而批次尚未完成

- **WHEN** 同批 `c1` 的重建结果已持久结算，运行器在第二项 `c2` 的派发意图保存前退出
- **THEN** 后继直接使用 `c1` 已保存结果，查询、执行、扣减均不重复。通过当前门禁后首次派发 `c2`
- **AND** 两项齐全并提交后，下一轮模型收到同序且各一份的配对结果

#### Scenario: 整批已提交或终态已提交

- **WHEN** 运行器分别在整批提交后、下一轮模型意图保存前退出，或在终态提交后、宿主收到结果前退出
- **THEN** 前者从下一轮模型开始，工具调用和结算均不重放。后者只返回已保存结果，后续模型、工具及回执查询均为零

#### Scenario: 查证后发生工作区变化或预算耗尽

- **WHEN** 已取得可信重建结果，此后在依赖工作区的下一步派发前无法核验原工作区，或剩余预算不能支撑该步骤
- **THEN** 保留原已知结算，阻止下一次派发，分别沿用工作区不可用或预算不足的原终止规则

### Requirement: 恢复使用部署绑定持有的稳定产物

可恢复 Run 的产物 MUST 绑定 `DurableArtifactStore` 并固定存储 ID。绑定 MUST 在已确认产物的有效期内，由新进程按原主体、Run 与版本提供有界分页读取。持久检查点和回执 MUST 只持有小结果和引用。恢复时 MUST 通过持久后端核验依赖的引用及其正文。

#### Scenario: 新进程读取部署绑定的完整产物

- **WHEN** 已确认的大产物有稳定引用，写入进程退出，后继进程用同一保留绑定恢复并分页读取
- **THEN** 页尺寸、偏移、总字节数和汇总哈希与原引用吻合，工具执行一次，持久回执和检查点中均无产物正文
- **AND** 跨主体、跨 Run、篡改引用和过期读取均返回产物不可用

#### Scenario: 保留能力不足或依赖的产物遗失

- **WHEN** 宿主开启依赖跨进程产物的恢复，但绑定没有对应保留能力，或已确认的原产物在恢复后无法核验
- **THEN** 能力不足的配置在受理时拒绝。已受理的 Run 遵循恢复失败规则，禁止继续依赖该产物，也不重发原调用以补写产物

### Requirement: 终态保留和恢复能力边界

恢复 MUST 在已配置的终态保留期内按原 `RunID` 返回持久结果，过期后按现有不可查契约处理。宿主开启的能力组合无法兑现恢复契约时，系统 MUST 在首次模型或工具派发前拒绝受理。

#### Scenario: 进程重启前后跨越终态保留期

- **WHEN** 使用同一保留策略的不同运行器进程在窗口内及窗口外分别恢复同一已完成 Run
- **THEN** 窗口内返回同一结果，过期后 `Recover` 返回原 Run 不可查，整个读取过程无新模型、工具或回执查询

#### Scenario: 选择尚无可恢复能力的上下文压缩绑定

- **WHEN** 宿主请求 `Recoverable`，模型绑定启用了尚不支持恢复的上下文压缩
- **THEN** 受理返回 `ErrRecoveryUnavailable`，无可恢复检查点且模型和工具派发均为零
