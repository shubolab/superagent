# run-lifecycle Specification

## Purpose

让 Go 宿主能够经本地 Mesh 启动一次 Run、消费实时模型文本、请求取消并独立读取最终结果。为纯文本闭环规定受理、事件、停止和模型调用的可观察行为。

## Requirements

### Requirement: 本地 Run 受理

系统 MUST 通过已绑定运行器受理授权主体的 Run，在受理时固定消息、模型和工具绑定、授权与有效预算，并维持同一运行器实例内的受理去重。

#### Scenario: 本地绑定与输入快照
- **WHEN** 宿主登记本地模型并以有效的非空 `RunID` 启动纯文本 Run
- **THEN** `Start` 回报已受理，唯一一次模型请求使用固定的模型、指令、历史和本次输入
- **AND** `Start` 返回后取消其调用上下文或修改原历史，Run 继续使用自己的上下文及原快照

#### Scenario: 未能受理
- **WHEN** 模型引用未登记、主体无权使用模型、`RunID` 为空或请求预算非法
- **THEN** `Start` 返回可识别的调用错误，Run 未受理，模型调用次数为零

#### Scenario: 相同启动请求重送与冲突
- **WHEN** 同一主体在同一运行器和保留期内，用相同 `RunID` 并发或顺序重送相同请求
- **THEN** 所有成功响应共用一次 Run 执行，纯文本 Run 最多发起一次模型请求
- **AND** 同一标识配不同请求返回启动冲突

#### Scenario: 工具和环境绑定受理
- **WHEN** 请求选择已登记工具及所需工作区能力
- **THEN** `Start` 校验主体授权和绑定，模型只看到本 Run 获准的工具
- **AND** 工具或所需环境绑定未获准时 `Start` 拒绝，模型和工具调用均为零

### Requirement: 模型完成与预算

运行器 MUST 在每次派发和接收处执行该 Run 的模型额度。有效的 `ModelCompleted(stop)` 按停止顺序裁决成功，有效的 `ModelCompleted(tool_calls)` 在具备工具绑定的 Run 中进入工具批次。

#### Scenario: 正常完成与消息增量
- **WHEN** 可控模型依次交付“你”“好”和完整答复“你好”
- **THEN** Run 以 `Succeeded` 结束，`Answer` 为“你好”，`Messages` 依次为本次输入和最终答复
- **AND** 历史快照及模型草稿留在各自的输入和观察路径

#### Scenario: 提前 EOF 或异常完成
- **WHEN** Run 在完整回复前遇到 EOF 或模型错误，或纯文本 Run 收到表示工具调用的完成原因
- **THEN** Run 以 `Failed` 结束，`Messages` 保留本次输入和此前已提交的完整轮次，`Answer` 为空，已交付增量仍可作为预览

#### Scenario: 模型输入超出有效额度
- **WHEN** Run 已受理，而完整模型请求的规范字节数超过有效输入上限
- **THEN** 本轮模型请求次数为零，`Wait` 取得 `BudgetExceeded` 及可区分的输入超限原因

#### Scenario: 模型输出等值与越界
- **WHEN** 回复的输出上限为六字节，模型交付“你”“好”及完整答复“你好”
- **THEN** 已交付的增量和重复的完整快照只计一次，六字节完整答复可成功
- **AND** 同样的模型输出在五字节上限下使 Run 返回 `BudgetExceeded`，模型流被关闭

### Requirement: 有界实时观察

每个 Run MUST 提供一次有界观察订阅。事件按 Run 连续编号，观察的停止和错误只影响该订阅。

#### Scenario: 顺序、终态与 EOF
- **WHEN** 观察者在有界缓冲和保留期内首次订阅正常完成的 Run
- **THEN** 依次读到 `run.started`、文本增量、`message.completed`、唯一的 `run.finished`，然后读到 `io.EOF`
- **AND** 文本增量可合并，合并后文本及连续 `Seq` 保持正确，终态与 `Wait` 一致

#### Scenario: 关闭或取消观察
- **WHEN** 宿主对阻塞的观察调用 `Close`，或取消观察上下文
- **THEN** `Recv` 解阻并分别报告流已关闭或上下文错误，Run 继续
- **AND** `Close` 可重复调用，后续订阅返回可识别的拒绝错误

#### Scenario: 慢观察者
- **WHEN** 暂停事件消费并使该订阅超过字节容量
- **THEN** 已缓冲的连续前缀先交付，随后报告溢出，`Wait` 仍能取得原 Run 的终态

### Requirement: 独立等待和稳定终态

系统 MUST 在保留期内向拥有者提供可并发、可重复读取的终态快照。等待上下文控制本次读取，提交的终态保持固定。

#### Scenario: 等待截止及多等待者
- **WHEN** 第一个 `Wait` 在模型阻塞时到期，随后模型完整结束，多个调用继续等待
- **THEN** 第一个调用返回上下文错误，后续调用得到同一逻辑结果及空 Go 错误
- **AND** 对一个返回快照的修改只影响该快照

#### Scenario: 用原标识读取或跨主体访问
- **WHEN** 拥有者以 `Client.Run(id)` 取得句柄，或另一主体使用同一标识尝试观察、等待或取消
- **THEN** 拥有者读取原 Run，另一主体得到记录不可查

### Requirement: 显式取消与到期

系统 MUST 将已记录的取消和 Run 截止传给在途模型，并按 Run 内的裁决顺序提交唯一终态。

#### Scenario: 取消先于模型完成
- **WHEN** 可控模型阻塞，运行器先接受 `Cancel`，模型随后尝试交付最终答复
- **THEN** 重复取消得到确认，模型收到停止信号且流能关闭，`Wait` 返回 `Cancelled` 和空 Go 错误
- **AND** 迟到答复留在已关闭的推进路径，终态中的 `Messages` 只含本次输入

#### Scenario: 模型成功先于取消
- **WHEN** 正常答复已提交成功终态，宿主随后调用 `Cancel`
- **THEN** 取消调用确认 Run 已结束，`Wait` 继续返回原成功快照

#### Scenario: Run 截止时间到达
- **WHEN** 模型流阻塞且 Run 截止时间先到达
- **THEN** 在途模型收到停止信号，`Wait` 返回 `TimedOut` 和空 Go 错误

#### Scenario: 两个 Run 的取消隔离
- **WHEN** 两个 Run 使用同一已登记模型并独立推进，宿主只取消其中一个
- **THEN** 被取消的 Run 收尾为 `Cancelled`，另一个 Run 仍可输出并完成，各自的观察和结果归属原 `RunID`

### Requirement: 完整工具批次驱动派发

运行器 MUST 在有效的 `ModelCompleted(tool_calls)` 后整批验证工具调用，按声明顺序逐个检查授权和预算，经 Mesh 派发 `Tool.Invoke`。可执行的调用须先取得所需的按次环境授权。

#### Scenario: 增量和无效批次尚未触发执行
- **WHEN** 模型仍在输出增量，或在完整回复前断流，或完成回复包含重复、缺失的 `CallID` 或非法参数结构
- **THEN** 工具调用次数为零。断流或无效完成以 `Failed` 收尾，当轮未提交

#### Scenario: 一个获准的搜索调用
- **WHEN** 模型交付有效的工具回复，声明 `CallID=c1` 的 `search`，且参数、授权和预算都通过
- **THEN** 运行器先产生 `message.completed`，取得按次授权后发出 `tool.dispatched(c1)`，收到可信回执后发出 `tool.completed(c1, succeeded)`
- **AND** 恰好发生一次 `Tool.Invoke`，回执关联原 `RunID` 和 `CallID`

#### Scenario: 派发前被拒与明确未执行
- **WHEN** 参数或权限校验失败，或派发后工具明确报告其尚未执行
- **THEN** 派发前拒绝发出 `tool.completed(rejected)`，`Invoke` 为零。已派发且明确未执行发出 `tool.completed(failed)`
- **AND** 有效的已知拒绝作为与原 `CallID` 配对的错误结果，可供后续模型轮次消费

### Requirement: 工具结果整批提交与回传

运行器 MUST 校验回执归属及状态。完整工具回复及全部可关联的结果一起提交，下一轮按原顺序读取这一批次。

#### Scenario: 完整工具链路
- **WHEN** 可控模型第 1 轮请求搜索 `docs/health.txt`，工具返回已知结果，第 2 轮用该结果形成最终答复
- **THEN** 模型请求共两次，工具执行一次，`Wait` 返回唯一的 `Succeeded`
- **AND** 第 2 轮收到本次输入、工具声明和配对结果。宿主增量依次含本次输入、助手工具声明、工具结果和最终助手答复

#### Scenario: 同轮多个调用
- **WHEN** 同一模型回复声明两个工具调用，第一项仍在途，随后两项分别返回成功和明确拒绝
- **THEN** 第一项结算后才处理第二项。两项都有可关联结果后整批进入下一轮，顺序与声明一致

#### Scenario: 缺少有效回执
- **WHEN** 运行器无法取得有效工具回执，且没有证据确认操作结局
- **THEN** 发出 `tool.completed(unknown)`，以 `ToolOutcomeUnknown` 收尾，停止详情关联原 `CallID`
- **AND** 当轮整体未提交，后续工具及模型派发为零

### Requirement: 模型和工具共用逐步预算

运行器 MUST 按 Run 余额授予每步额度，结算工具尝试、扫描用量、规范模型输出和完整工具回执。模型派发前重新检查输入字节、剩余调用次数、共享输出和期限。

#### Scenario: 扫描及回执结算
- **WHEN** 搜索获授 32 字节扫描额度并成功读取 13 字节，工具返回可核对的有界回执
- **THEN** 扫描额度结算 13 字节，工具尝试结算一次。共享输出结算两轮的模型输出及完整回执，每份模型增量和完成快照的重复内容只计一次

#### Scenario: 工具准入额度不足
- **WHEN** 工具次数为零，或共享输出不足以容纳最小关联回执
- **THEN** `Invoke` 与实际读取均为零，Run 以 `BudgetExceeded` 收尾

#### Scenario: 已知拒绝计入预算
- **WHEN** 一个结构有效的拟调用进入校验，随后因参数或权限被拒
- **THEN** 工具尝试次数仍扣一次，可回传的拒绝结果计入共享输出

#### Scenario: 工具结果已提交而下一轮额度不足
- **WHEN** 工具批次已完整提交，余下模型次数、输入字节或共享输出不足以准入下一轮
- **THEN** 第 2 轮模型请求为零，`Wait` 返回 `BudgetExceeded`，消息增量保留完整的工具轮次

### Requirement: 工具派发与停止裁决

运行器 MUST 在同一 Run 内裁决派发、提交、取消和截止。执行结局与资源清理分别确认，等待工具回执的时间有上限。

#### Scenario: 取消先于工具派发
- **WHEN** 运行器在工具完成回复之后、越过派发边界之前记录取消
- **THEN** 工具执行为零，已发出的按次授权撤销，`Wait` 返回 `Cancelled`

#### Scenario: 可判定的在途工具被停止
- **WHEN** 已派发的搜索收到取消或达到 Run 截止，环境与工具能确认操作结局
- **THEN** 运行器按原停止原因返回 `Cancelled` 或 `TimedOut`，后续派发为零，环境清理可独立确认

### Requirement: 本地启动回执丢失

在运行器可能已经受理、但 Mesh 无法交付启动响应时，SDK MUST 报告受理结果不明。宿主可用原绑定与 RunID 查询原 Run，或在保留期内重送相同请求。

#### Scenario: 已受理但启动响应丢失
- **WHEN** 进程内替身只丢弃一次已经受理的启动响应
- **THEN** Start 返回可识别的受理结果不明，原标识可查询
- **AND** 重送相同请求取得相同 Run，模型与工具副作用不会重复

### Requirement: 本地工具回执与资源释放独立

Mesh MUST 分别确认未交付和可能已执行但回执不明。运行器按工具回执判断副作用，按环境确认判断清理。

#### Scenario: 文件已经保存但没有收到回执
- **WHEN** 受控测试工具确认一次写入，随后其响应丢失，环境已释放
- **THEN** 写入一次，无调用重试，无下一轮模型请求
- **AND** 终态为 ToolOutcomeUnknown，关联原调用，当轮未提交，清理状态独立可查

### Requirement: 并行 Run 的观察与执行隔离

运行器 MUST 隔离各 Run 的观察、预算、截止及工具执行。

#### Scenario: 观察关闭或溢出时独立 Run 继续
- **WHEN** 甲停在慢工具，且其观察关闭或缓冲溢出，乙同时开始推进
- **THEN** 乙可独立完成，甲仍可等待或显式取消，各自事件和结果归属正确

#### Scenario: 截止触发停止
- **WHEN** 可控时钟推进到 Run 截止，已派发工具迟迟无法给出可验证回执
- **THEN** 上下文截止传给在途工具，经过有界回执等待后提交 ToolOutcomeUnknown，后续工作未派发
