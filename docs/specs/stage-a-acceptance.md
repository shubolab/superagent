# 阶段 A · 最小闭环与端到端验收

设计评审稿。基线是一个 Go 宿主经进程内 Mesh 运行两轮模型、中间执行一次受授权的本地工具，并取得一个可重复读取的终态。宿主传入固定历史快照。 [阶段 A 契约](stage-a-bypass.md)

## 固定的本地 Run

| 输入 | 固定内容 |
| --- | --- |
| 宿主装配 | 通过 `NewMesh → NewClient → Start` 走正常入口，登记可控的流式模型 `chat`、有界搜索 `search`、本地环境。宿主只授权该 Run 用 `search` 读取工作区的 `docs/` |
| 工作区与消息 | 临时工作区内的 `docs/health.txt` 内容为 `status=ready\n`，共 13 字节。宿主传入“查一下服务状态”，使用空历史 |
| 测试预算 | 模型请求 2 次，工具尝试 1 次，搜索扫描额度 32 字节。Run 累计模型输入上限 64 KiB、共享输出上限 4 KiB。用宿主可控时钟设定截止时间。这些数值用于该用例 |
| 可控模型 | 第 1 轮先交付文本增量，再给 `ModelCompleted(tool_calls)`，唯一调用为 `search`，`CallID=c1`，参数为路径 `docs/health.txt` 和匹配词 `status`。第 2 轮校验收到配对结果后，流式返回“服务状态为 ready。”及 `ModelCompleted(stop)` |

| 顺序 | 必须看到的证据 |
| --- | --- |
| 受理与流 | `Start` 返回已受理句柄。`Observe` 从 `run.started` 开始。第 1 轮在完整回复到达前暂停，工具派发与实际执行均为零 |
| 权限与派发 | 完整回复经过整批校验后发布 `message.completed`。运行器核对授权和预算，取得按 `c1` 签发的环境授权，再发布 `tool.dispatched`。工具与环境各自复核后，只执行一次有界读取 |
| 回执与结算 | `tool.completed(c1, succeeded)` 关联原调用。工具结算 13 字节扫描量，运行器按规范计量扣除两轮的模型输出与完整工具回执，重复出现在增量和完成快照中的文本只计一次 |
| 下一轮输入 | 第 2 轮输入依次为本次用户消息、含 `c1` 的助手工具声明、配对的工具结果。结果包含 `status=ready`，指令和获准工具沿用受理快照 |
| 唯一终态 | `run.finished(Succeeded)` 只发布一次，正常观察随后收到 EOF。`Seq` 在 Run 内连续递增。`Wait` 返回相同终态和四条消息，依次为用户、助手工具声明、工具结果、最终助手答复。保留期内重复 `Wait` 得到相同的逻辑快照 |

## 实现顺序

| 顺序 | 交付切片 | 通过条件 |
| --- | --- | --- |
| 1 | **SDK、运行器和本地 Mesh。** 先用可控模型跑纯文本，接通 `Start`、`Observe`、`Wait`、`Cancel`，落实模型绑定授权、Run 期限和模型字节限额 | 纯文本流正常收尾，错误绑定在装配或受理时失败。观察超时只影响观察，显式取消可停止在途模型。 [SDK 契约](go-sdk-contract.md) · [Mesh 契约](mesh-transport.md) |
| 2 | **有门禁的工具闭环。** 接通 `ModelCompleted → Tool.Invoke → 下一轮`，同一切片落实按次授权、有界读取、工具预算和整轮消息提交 | 固定 Run 通过，且在模型停在完成标记前、参数越权或额度不足时，受影响工具执行零次。 [模型流](model-adapter.md) · [权限门禁](run-authorization.md) · [预算](run-budget.md) |
| 3 | **停止、失效和资源边界。** 用可控时间和传输替身覆盖断流、丢回执、取消、观察溢出及大文件。增加两路 Run 验证隔离 | 下方基线验收清单全部通过，记录调用次数、终态、消息和环境清理状态。 [执行环境](execution-environment.md) · [工具生命周期](tool-call-lifecycle.md) |
| 4 | **一个真实供应商适配器。** 按宿主工厂接入，用同一状态查询执行独立的供应商冒烟 | 固定历史下验证真实流的完成标记，通过供应商规范化后的 `CallID` 核对工具调用和回传。装配错误与 Run 内认证或模型请求失败各在对应入口可见。 [模型工厂](model-factory.md) |

阶段 A 的内核基线以第 1 至 3 步的本地确定性用例验收。第 4 步验证实际供应商接入，单独记录供应商与模型绑定。

## 端到端验收清单

用例之间使用新的 Run 和独立工作区。可控模型按用例核对下一轮应收到的结果。带竞态的用例以调用暂停点、可控流和时钟定位先后。从公开 SDK 入口启动，核对事件相对顺序、`Wait` 结果、调用计数、预算和文件操作。允许合并文本增量及插入可选进度事件。

| 用例 | 输入或故障 | 可判定的通过条件 |
| --- | --- | --- |
| 正常闭环 | 固定的本地 Run | 两次模型请求、一次工具尝试及执行、一个成功终态，消息、回执和预算与上表一致 |
| 受理拒绝 | 用同一宿主请求无权使用的模型 | `Start` 返回授权错误，Run 未创建，模型和工具调用均为零 |
| 启动回执丢失 | 运行器受理后丢掉启动回执，在同一实例及保留期内用原 `RunID` 查询或重送相同请求 | 原 Run 可查询，受理一次，后续模型和工具调用次数与正常闭环相同 |
| 模型未完成 | 第 1 轮在 `ModelCompleted` 前 EOF 或交付结构无效的完整回复 | `Failed`。工具执行为零，`Result.Messages` 只含本次输入 |
| 参数与权限拒绝 | 模型参数不符、请求 `docs/` 之外的路径，或环境拒绝签发按次授权。另注入过期或跨调用的环境授权 | 派发前拒绝产生 `tool.completed(rejected)`，工具执行为零，拒绝结果按 `c1` 回传。派发后凭证无效时实际操作也为零，有明确未执行回执时映射为 `tool.completed(failed)` |
| 调用预算耗尽 | 将固定 Run 的模型次数降为 1，或将工具尝试次数降为 0 | 前者保留已提交的工具轮次，第 2 轮请求为零。后者工具派发为零。终态均为 `BudgetExceeded` |
| 模型流字节边界 | 固定本轮输出上限，分别让完整回复恰好达限和多一字节 | 达限时接受完整回复。多一字节时关闭本轮流，以 `BudgetExceeded` 收尾，本轮工具派发为零 |
| 搜索资源上限 | 维持扫描、单行缓冲和回执上限，把输入增大为零命中长文件或超长单行 | 实测扫描和缓冲保持在配置上限内，结果报告覆盖不完整及原因，另一路 Run 可继续 |
| 取消和超时 | 在第一次工具派发前取消，或阻塞模型流后推进至 Run 截止。另测已派发且效果可判定的工具 | 停止先于派发时工具执行为零。显式取消及到期分别为 `Cancelled` 和 `TimedOut`。在途流或工具收到取消，环境可独立确认清理 |
| 两个工具同轮 | 提高工具次数额度，让同一回复声明两次调用。控制第一项回执到达时机，再分别让第二项回执齐全或效果不明 | 按声明顺序派发。齐全时整组进入下一轮。效果不明时当轮整体未提交，第 2 轮请求为零 |
| 已写入、回执丢失 | 换成获准的测试写入工具，保留工作区，在确认一次写入后丢回执 | 文件确实写入一次，重派发和第 2 轮模型请求均为零。`Wait` 返回 `ToolOutcomeUnknown`，`Stop` 关联原调用，未提交轮次留作诊断 |
| 观察断开和并行隔离 | 甲停在慢工具时启动乙。关闭甲的观察，另测甲的观察缓冲溢出或显式取消 | 关闭与溢出只结束甲的观察，仍可等待甲的终态。取消甲只影响甲。乙能流式输出并完成，事件和消息归属正确 |

## 上下文压缩接入门槛

第 1 至 4 步通过后，按宿主策略和模型绑定单独接入压缩，初始关闭。首轮和每次后续模型派发前都检查。如涉及上一工具轮次，待整批提交后再计量并裁决候选视图。

- **接入前**，所用模型绑定须在真实适配链路上验证输入计量、有效窗口及安全余量。先记录同一批固定历史长任务的成功率、预算和耗时作为基线。
- **启用前**，通过压缩接口用例，再用相同长任务检查用户约束原文、工具配对、原文回查、失败回退和最新消息保留。工具重放次数应为零，`Result.Messages` 继续从原始已提交消息生成。记录含摘要开销的总成本和时延。 [压缩接口与验收用例](context-compaction-contract.md#验收用例)
