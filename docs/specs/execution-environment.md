# 执行环境契约

阶段 A 设计稿，更新于 2026-11-27。需要工作区的 Run 绑定一个受限环境句柄，工具按次获得授权。环境可以在本机、沙箱或远程节点运行。远程节点也可以运行沙箱。组件间操作通过 Mesh 传输。

## 绑定与按次授权

| 对象 | 范围与职责 |
| --- | --- |
| 工作区引用 | 标识已有或新建的工作区及其所有者、保留策略。可保留的工作区使用稳定标识和可查版本 |
| 环境句柄 | 环境组件签发，绑定 `RunID`、工作区、环境实例、有效额度和到期条件。由运行器持有 |
| 调用授权 | 同时绑定运行器、主体、`RunID`、`CallID`、环境、工作区和目标工具身份，并限制路径、操作类型、有效额度及截止时间。工具只获得本次调用的授权 |
| 产物引用 | 引用已完成的产物及其版本、字节数、内容哈希和可用期限。访问由产物所有者授权 |

运行器在受理时按宿主配置固定模型和环境绑定。建议在首次需要工作区的调用前分配环境。无需工作区的 Run 可直接执行。每次派发前，运行器根据宿主授权、工具声明及 Run 剩余额度申请调用授权。环境组件在使用授权时复核范围和有效期。

| 行为 | 发起者及保证 |
| --- | --- |
| 查询能力与分配环境 | 运行器请求。环境公布可兑现的能力和范围，确认资源和额度已分配后返回句柄、工作区引用及生效上限。同一分配请求最多生成一个句柄，回复丢失时可用原请求身份查询，未确认的分配由环境到期回收 |
| 授权并操作工作区 | 有权使用 Run 句柄的运行器申请本次授权。工具提供方凭授权请求文件或进程操作，环境按调用身份及实际访问对象复核。 [按次复核](run-authorization.md#按次授权怎么复核) |
| 取消、释放与查询状态 | 运行器发起，环境返回请求受理、工作已停止或资源已释放等可区分的状态。重复清理请求沿用原句柄，可查询当前进度 |

授权和操作是行为边界，具体 RPC 和 Go 签名待定。 [工具调用契约](tool-call-lifecycle.md)

## 资源声明和执行

环境声明每项能力能否**强制限制、仅可计量或不可用**，同时说明单位、作用范围及超限动作。运行器根据宿主上限、Run 剩余额度和工具要求决定是否分配。工具带硬要求时，只有实际可兑现的绑定才获准派发。运行中沿用已选绑定，每次授权按剩余额度收紧。

| 资源 | 执行规则 |
| --- | --- |
| 内存与进程 | 通用命令启动前对整组进程及其后代设置限制。环境保留运行器容量，按环境可用容量接纳并发工作。超限时记录证据并回收对应工作负载。 [大文件搜索验收](run-budget.md#大文件搜索验收) |
| 执行时限 | 环境独立执行实际截止时间。每次调用的时限受 Run 期限和环境句柄到期条件约束。远程连接断开后，执行节点继续执行已接受的截止规则 |
| CPU | 有 CPU 限额能力的环境单独声明控制的单位和作用范围，例如用量时间或配额比例 |
| 工作区与产物存储 | 分别声明可写范围和可执行的磁盘额度。工作区、产物和共享挂载按各自可兑现的额度计量。工具的扫描量、缓冲和返回字节仍按工具契约约束 |

| 部署 | 能力声明依据 | 如何执行 |
| --- | --- | --- |
| 本机 | 声明当前宿主实际可用的隔离、进程范围和限额 | 受控的进程内工具使用有界读写和并发控制。通用命令使用宿主已验证的进程组限制 |
| 沙箱 | 分别声明进程隔离、文件与网络范围，以及实际生效的内存、时限和磁盘限制 | 启动前配置沙箱与资源控制。工作区按批准范围挂载，共享存储的限制由其所有者单独声明 |
| 远程 | 由执行节点报告当前部署能力，分配时确认实际配置 | 执行节点使用本机或沙箱机制执行限制，并把超限证据、停止和释放状态经 Mesh 返回 |

可用 Linux cgroup v2 和 Windows Job Objects 验证进程组控制能力。具体是否覆盖全部后代、是否支持磁盘额度和异常回收，仍由对应环境单独验收。 [Linux cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html#memory) · [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)


内置本地读取环境通过 `DescribeRead` 公布可强制的扫描、时限、并发和等待上限。默认每次读取最多 1 MiB，同一实例同时容纳 8 个读取许可和 16 个等待。宿主可用 `NewLocalReadEnvironmentWithOptions` 修改上限。等待发生在按次授权签发前，队列满时回报 `environment_busy`。
## 取消与清理

1. 运行器在取消生效后停止授权和派发，通过 Mesh 通知工具提供方与环境。清理使用单独的有界操作期限，即使 Run 的执行上下文已结束也能发出请求。
2. 环境收到请求后停止接纳新操作，向在途工作发送取消。协作停止到期后，环境按已声明能力终止整组进程，回收本次 Run 的运行资源，再按保留策略处理工作区和产物。
3. 环境能确认在途工作已结束及运行资源已回收后，才报告已释放。远程断开时，运行器将清理记为待确认，节点继续按截止时间和句柄到期策略处理，重连后按原句柄查询。

运行器裁决 Run 终态。工具提供方确认工具效果。环境组件确认资源清理。三类状态分别报告。`Wait` 可以先返回 Run 终态，已保存文件按原保留策略处理。 [派发后断连的收尾语义](tool-call-lifecycle.md#阶段-a-收尾)

## 工作区和产物保留

| 内容 | Run 结束时的处理 |
| --- | --- |
| 环境句柄与调用授权 | 随 Run 收尾失效。后续 Run 访问同一工作区时，重新分配绑定及按次授权 |
| 临时工作区 | 环境按配置回收。需保留的完整产物在回收前转到相应的保留位置，移交失败时报告状态并按保留期限处理 |
| 宿主已有或显式保留的工作区 | 按原所有者策略保留。运行器归还本次运行资源，后续使用稳定的工作区标识和版本重新绑定 |
| 完整产物 | 存在工作区或独立产物位置，用有界引用交给宿主。保留期和访问授权共同决定引用的可用期限 |
| 部分产物 | 按配置清理或短期保留为诊断，标明未完成 |

阶段 B 的恢复记录保存工作区身份、所需版本和产物引用，保留期覆盖核对窗口。恢复依赖原工作区时，运行器核验它仍可访问，待环境确认旧执行已停止或已阻断旧执行的写入后再继续。工作区不可查或旧写入尚未确认时，沿用待核对规则。 [阶段 B 恢复](tool-call-lifecycle.md#阶段-b-恢复)

## 验收场景

| 场景 | 应得到的结果 |
| --- | --- |
| 阶段 A 使用进程内环境提供方 | 报告实际能力和生效额度，要求超出能力时在派发前返回明确错误。远程环境随远程传输验收 |
| 两次工具调用共享一个工作区 | 各自只能使用本次获授的路径和操作。过期或跨调用复用的授权被拒绝 |
| 通用命令的子进程触发内存上限 | 环境报告限制命中，回收对应工作；其他 Run 与运行器继续 |
| 已分配环境后连接中断或取消 | 节点按期限停止工作。清理可以查询；能确认释放时才报告成功 |
| 取消时已有文件保存或只有一部分输出 | 已确认的文件按工作区策略保留，部分产物按诊断策略处理。Run 终态与文件保留状态可分别观察 |
