# 阶段 A · bypass 权限门禁

宿主预先授权，运行器按同一份 Run 授权推进，无需逐次人工批准。阶段 A 信任宿主和已登记的进程内 Go 组件，由它们共同执行权限检查。需要进程级隔离的工具必须绑定能兑现隔离要求的执行环境。

## 宿主授予 Run

| 输入 | 决定的边界 |
| --- | --- |
| 宿主的身份上下文 | 宿主认证调用主体，并经受信的 Mesh 上下文传入。模型消息、工具参数和公开的 `RunID` 或 `CallID` 只用于业务输入或关联 |
| 宿主授权配置 | 按主体限定可用的模型和工具引用，按工具限制适用的业务范围、工作区、路径和操作。需要某类权限但配置缺失时拒绝 |
| `StartRequest` | `Model` 和 `Tools` 选取本次需要的绑定，空工具列表表示纯对话。`Environment` 表达所需能力。引用须已登记，所申请范围须处于宿主授权之内 |
| 运行器的授权快照 | 受理成功后固定主体、绑定、工具声明及授权范围。用快照生成给模型的工具清单。权限不足时拒绝整个 `Start` |

运行器从宿主获准的工作区中选择环境绑定。宿主更新授权配置后，新 Run 使用新配置。需要收回已受理 Run 的权限时，宿主发出 `Cancel`，运行器停止新派发并请求环境撤销在途调用的授权。工具提供方仍可依据当前业务规则拒绝调用。`Observe`、`Wait` 和 `Cancel` 在同一运行器内按已验证主体和 `RunID` 查找，其他主体的 Run 返回记录不可查。 [SDK 启动与生命周期](go-sdk-contract.md#启动与生命周期)

## 运行器派发前检查

1. 接受完整的 `ModelCompleted`，先校验整批 `CallID` 和参数结构。对结构有效的批次，按声明顺序处理调用，并按预算契约检查停止条件和扣减工具尝试次数。
2. 在本 Run 的可见清单中解析工具名，校验参数约束，并检查参数要求的业务和资源范围。调用只能使用首次受理时固定的工具绑定。
3. 需要环境的调用从原 Run 句柄申请 `EnvironmentGrantRef`。授予范围取宿主授权、工具声明、本次实际需要以及环境可兑现范围的交集，另受额度和期限约束。实际需要无法满足时拒绝派发。
4. 运行器在派发边界再次裁决预算、期限和取消。通过后发出 `tool.dispatched`，经 Mesh 提交一次 `Tool.Invoke`。停止先于派发生效时，撤销已为该调用取得的授权。

[模型工具派发边界](model-adapter.md#工具派发边界) · [预算与扣减](run-budget.md#预算与扣减)

## 按次授权怎么复核

| 组件 | 执行检查 |
| --- | --- |
| Mesh | 依据实际发起组件的绑定传递身份。阶段 A 用 Mesh 管理的内部上下文传递运行器固定的按次授权，沿用 `Tool.Invoke(ctx, req)` |
| 工具提供方 | 在业务操作前验证发起者是本 Run 的运行器，核对主体、目标工具绑定、`RunID`、`CallID`、有效期和实际参数范围，再执行本工具的业务授权。需要环境时使用本次授权引用经 Mesh 请求操作 |
| 执行环境 | 核验运行器有权从该 Run 句柄申请授权。每次使用时检查真实工具身份、Run 和 Call、工作区、操作类型、实际访问对象、额度及期限。路径检查与打开在同一受控操作内完成，链接解析后的对象也必须在获授范围内 |

`EnvironmentGrantRef` 指向环境持有的授权记录，绑定运行器、主体、`RunID`、`CallID`、目标工具、环境和工作区。同一调用可在范围内执行多次环境操作。调用结束、取消撤销或授权到期后拒绝新操作，在途操作按环境的取消规则停止。 [工具请求](tool-invoke.md#toolrequest) · [环境绑定与按次授权](execution-environment.md#绑定与按次授权)

例如，宿主为本次 Run 选择 `search`，只授予该工具读取工作区内 `docs/` 的权限。运行器拒绝请求范围外路径的参数。环境复核搜索实际尝试打开的文件，拒绝解析到 `docs/` 以外的对象。

## 拒绝如何回报

| 拒绝位置或证据 | 对外回报 |
| --- | --- |
| `Start` 授权不足 | SDK 返回可识别的拒绝访问错误。未创建 Run，模型和工具执行次数均为零 |
| 运行器校验失败，或环境拒绝签发按次授权 | 发布关联原 `CallID` 的 `tool.completed(rejected)`。无 `tool.dispatched`，`Tool.Invoke` 执行次数为零 |
| 已派发，工具或环境拒绝，提供方确认尚未开始业务操作 | `ToolResult.State=not_executed`，带拒绝原因，运行器发布 `tool.completed(failed)` |
| 已派发，后续操作被拒，已执行部分的效果可确认 | `ToolResult.State=known` 且 `Completion.Outcome=failed`，保留已确认效果，运行器发布 `tool.completed(failed)` |
| 已派发，缺少足够证据确认效果 | 发布 `tool.completed(unknown)`，以 `ToolOutcomeUnknown` 收尾 |

已知拒绝可随完整工具批次回传模型，使用原 `CallID`、稳定短原因码和限长说明。未获授的工具名和未登记的工具名均回报 `tool_not_allowed`，已获授工具的参数错误用 `invalid_arguments`，范围或业务权限不足用 `access_denied`。公开回报只含关联字段和可披露的原因，宿主诊断可记录拒绝阶段及组件。需改正时由模型提出带新 `CallID` 的调用，继续受同一授权与预算约束。 [SDK 工具事件](go-sdk-contract.md#事件类型与顺序) · [跨边界工具回执](tool-invoke.md#go-error-与回执)

## 验收场景

| 场景 | 预期 |
| --- | --- |
| `search` 获准读取 `docs/`，一次调用中读取两份文件 | 同一按次授权用于两次获准读取，工具结果按原 `CallID` 回传 |
| `Start` 请求已登记但主体无权使用的工具，或模型消息声称权限已提升 | 越权的 `Start` 被拒。消息照常按输入处理，Run 权限不变。空 `Tools` 只允许纯对话 |
| 已受理的 Run 请求隐藏工具，或以读权限请求写入 | `tool.completed(rejected)`，工具执行零次。模型得到有界且可关联的说明 |
| 换主体、Run、Call、工具或工作区复用引用，或授权已撤销、到期 | 环境拒绝，目标操作零次。另一个主体也无法用已知 `RunID` 观察、等待或取消原 Run |
| 路径通过链接解析到授权范围外 | 环境拒绝越界对象的访问。已确认的操作结局仍随回执保留 |
| 取消与工具派发同时发生 | 取消先被运行器裁决时执行零次。已过派发边界时，撤销后无新环境操作，既有操作按回执证据收尾 |
| 第一个操作已保存文件，第二个操作被拒，或回执在返回时丢失 | 有可信回执时为已知失败并保留已确认效果。缺少效果证据时 Run 停在 `ToolOutcomeUnknown` |
