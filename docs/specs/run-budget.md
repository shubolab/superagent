# 阶段 A · Run 预算契约

运行器维护每个 Run 的有效额度和已用量。宿主提供有限默认值、硬上限及单次上限。受理时用请求值与宿主上限取小，省略的维度使用宿主默认值。时限及模型相关额度须为正数，工具次数、扫描和原始输出额度可显式设为零。无效预算拒绝受理。数值默认值随首版负载验收确定。 [阶段 A 推进规则](stage-a-bypass.md#推进规则)

## 预算与扣减

| Run 级维度 | 计量时机 |
| --- | --- |
| 执行期限 | 从受理起走同一份墙钟时间，包含环境准备、模型和工具。单次操作取 Run 截止时间、操作时限及适用授权到期时间中最早的一项 |
| 模型请求次数 | 运行器每发起一个模型请求扣一次 |
| 工具请求次数 | 结构有效的工具批次按顺序处理。每进入一个拟调用的校验就扣一次，包含参数不符或未授权的拟调用 |
| 模型输入字节 | 每次发起请求前按规范输入快照计量，包含指令、消息和工具声明。同一历史发给模型两次就计两次 |
| 共享输出字节 | 累计模型规范输出及工具的完整有界回执，含关联字段和产物引用。运行器生成并回传模型的工具拒绝结果也计入 |
| 工具扫描及原始输出字节 | 两项独立累计。按受管文件读取量，以及受管输出字节计量。命令的 stdout 和 stderr 共享原始输出限额，落盘和生成预览时沿用同一次计量 |

字节维度按 UTF-8 或原始二进制字节计量。模型输入和工具回执使用 SDK 数据的紧凑 JSON 字节数作为统一计量口径。模型输出按规范文本、工具 ID、名称及原始参数字节计量，流式增量和完成快照中的相同内容只计一次。供应商用量可单独报告。 [模型适配器计量](model-adapter.md#请求)

## 怎么分给模型和工具

1. 阶段 A 的同一 Run 串行推进。运行器在每次派发前检查各维度，单次额度逐项取 **Run 余额、宿主单次上限、适用的组件或环境上限** 中的最小值。模型和工具按需共用输出余额。
2. 模型拿到 `MaxOutputBytes`。工具通过 `ToolRequest.Limits` 收到 `MaxResultBytes` 及适用的 `MaxScanBytes`、`MaxRawOutputBytes`。派发或回传拒绝前，先确认结果额度容得下带实际标识的最小回执。工具提供方和环境按职责限制用量，并报告可核对的扫描和原始输出字节。
3. 次数和模型输入按上表扣减。运行器在单次工作收尾后按实际输出和扫描量结算，余额留给下一步。适用的维度缺少可信用量时按授予额度结算，同时保留实际用量未知的状态。
4. 正好达到上限的完整结果可接受。后续步骤需要的额度不足时才停止。例如工具用完共享输出余额后，已完成的工具轮次仍可提交，下一次模型请求以预算不足收尾。

例如共享输出剩余 56 KiB，本次工具回执上限为 12 KiB，实际回执用了 2 KiB。下一步共享余额为 54 KiB。文件读取和落盘产物另按扫描、原始输出和存储限额计量。

## 流式限额在哪里执行

| 责任方 | 执行位置 |
| --- | --- |
| 模型适配器 | 拉取、解码并组装模型输出时，控制单帧、单字段、缓冲和本轮累计字节。扩容前检查上限，超限立即关闭供应商的流并报告命中的额度 |
| 工具提供方 | 分块读取与处理，每次读取受剩余读取量和块大小约束。追加缓冲或写产物前检查原始输出上限，交付前检查完整回执大小。优先保留最小回执和限长摘要 |
| 执行环境 | 执行获授的工作区读写、进程树内存、时限、存储等硬额度。通用命令须在启动前具备所需能力 |
| Mesh | 控制单帧和排队缓冲，传播取消及限额错误。保留组件原有的内容和计量口径 |
| 运行器 | 组装模型输入时按上限计量，接受模型增量、完成快照和工具回执前复核。超限部分到此为止，既有可展示前缀及完整已提交消息按各自规则保留 |

阶段 A 的工具输出在执行侧分块读取或落盘。运行器接收有界回执，模型上下文只收规范的小结果或产物引用。流中的单帧、队列字节与累计业务输出分别受限，观察队列溢出只结束观察。 [工具大输出](tool-call-lifecycle.md#大输出与结果大小) · [Mesh 流契约](mesh-transport.md#普通请求与流)

## 超限与收尾

| 触发条件 | 运行器行为 |
| --- | --- |
| Run 截止 | 停止新派发并取消在途工作，已派发工具效果可判定时以 `TimedOut` 收尾 |
| 额度不足以准入下一步，或命中模型输出的字段、单帧或累计字节上限 | 停止新派发，取消或关闭在途工作，以 `BudgetExceeded` 收尾。模型未完成的轮次仅留已交付草稿，工具派发次数为零 |
| 工具主动按次限额结束，或单次时限到期，且有有效回执 | 报告已知的部分结果或资源失败。在下一步仍满足 Run 准入条件时，可将结果交给模型缩小范围 |
| 工具超限后回执无效或缺失 | 停止后续调用。可信证据足以判定效果时，额度超限以 `BudgetExceeded` 收尾。效果仍不明时以 `ToolOutcomeUnknown` 收尾 |

运行器在同一派发边界裁决预算、取消与终态。停止后关闭数据流，在有界期限内确认在途工具的可核对回执，再提交 `Result` 并发布唯一的 `run.finished`。预算停止详情包含维度、作用范围、上限、可确认用量及适用的 `Step` 或 `CallID`。终态控制信息和诊断有独立的小体积上限，执行额度用尽后仍可交付。资源清理可在终态发布后继续，使用独立的有界期限，工作区和部分产物按原策略处理。 [SDK 终态](go-sdk-contract.md#调用错误与运行终态) · [执行环境清理](execution-environment.md#取消与清理)

## 大文件搜索验收

首版面向模型提供有界文本搜索。限制候选文件、单文件和累计读取、查询与单行缓冲、命中数、预览和回执。实际读取量按块扣减，遍历和读取都能取消。进程内搜索的并发数和等待队列也要有上限。通用 `grep` 只在能强制限制整个进程树内存与时限、并能按限额回收的环境内执行。stdout 和 stderr 超限时请求环境停止工作，管道和进程树按有界期限收尾。 [文件搜索资源边界](tool-call-lifecycle.md#文件搜索的资源边界)

| 验收输入 | 预期结果 |
| --- | --- |
| 大文件零命中、扫描中继续增长 | 达到读取上限即停止。结果带已扫字节和覆盖状态。未确认完整扫描时报告部分覆盖，空结果仍可能有未发现的命中 |
| 单行超过缓冲上限、短行大量命中 | 单行超限报告覆盖不完整。大量命中时回执和预览仍在限额内。放大文件和并发请求，核对进程内搜索的峰值内存随上限收敛 |
| 通用命令的子进程触发环境内存上限 | 环境回收进程树并报告可核对的资源错误。记录执行组和运行器的峰值内存，另一路 Run 可继续 |
| 两次搜索各自低于单次上限、合计达到 Run 上限 | 后一次最多取得剩余扫描或输出额度，已读字节仍计入。后续需要该维度的调用按余额准入 |
| 完成快照重复已有增量、流刚好达上限或多一个字节 | 正常重复只计一次。完整结果恰好等于上限可接受，多一个字节时停止模型流且本轮零工具派发 |
| 模型输出和工具回执轮流消耗共享余额 | 每次只扣本次计量，后续单次授予不超过余额。超限时仍能读取终态和此前已提交消息 |
