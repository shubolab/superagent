# 阶段 A · bypass 执行内核

状态为待审提案。阶段范围见 [SuperAgent 总体架构](architecture.md)，接口及宿主可见行为见 [Go SDK 契约与行为接口](go-sdk-contract.md)。

## 一次运行的边界

宿主通过 Mesh 启动一次 Run，由一个运行器推进。从第一条模型请求开始，到给出最终答复，或因取消、超时、预算和错误而停止。SDK 宿主与 TUI 使用同一份契约，阶段 A 的运行器及其依赖使用进程内绑定。

| 方向 | 宿主与内核之间的契约 |
| --- | --- |
| 启动 | 宿主提供指令、本次输入、可选历史、模型绑定、可调用工具、预算及可选的执行环境要求。运行器在开始时取得固定的输入和能力绑定，宿主的后续修改影响新的 Run |
| 执行 | 运行器自动推进模型与工具循环。模型提出工具调用，运行器校验后经 Mesh 派发。需要工作区的工具使用已绑定的环境，工具结果交回模型 |
| 控制 | 启动后可观察进度、等待最终结果或主动取消。取消和等待分别有自己的生命周期 |
| 输出 | 终态给出停止原因、完整最终答复（成功时）、已完成的消息增量和可取得的用量。宿主决定何时将增量提交为会话历史 |

A 的临时状态保存在拥有 Run 的运行器实例内。会话历史管理、持久化检查点、重启续跑、人工审批、运行中注入输入和工具结果接管都留给后续设计。

## bypass 的授权语义

宿主按已验证主体和本次 `StartRequest` 固定可用工具及范围。运行器在授权范围内自动推进，派发前检查工具、参数、资源与预算。工具提供方复核业务权限，执行环境复核实际操作。 [Run 授权、按次复核与拒绝](run-authorization.md)

## 推进规则

1. 校验启动输入并建立一次运行。输入校验失败时直接返回，已接受的 Run 则各自提供唯一终态。
2. 调用模型适配器。文本增量可立即展示，运行器收到并校验 `ModelCompleted` 后才继续处理本轮答复或工具。流中断、截断或缺少完成事件时，草稿可以保留给界面查看。 [模型流契约](model-adapter.md#流式事件与完整回复)
3. 完整答复没有工具调用时，成功结束。若包含工具调用，先验证整批调用的关联标识，例如重复或缺失的调用 ID 属于模型协议错误。通过后，按声明顺序逐个检查名称、参数和预算，派发并关联结果。工具结果齐全且停止尚未生效时，先提交整轮，再判断是否继续。首版在同一 Run 内串行执行工具，可少处理批内依赖和副作用顺序，代价是同轮独立工具的等待时间叠加。 [消息提交边界](message-assembly.md#工具结果何时进入上下文)
4. 工具名不在授权列表、完整 JSON 参数未通过工具校验或工具明确返回业务失败时，构造可与原调用匹配的错误结果，允许模型在剩余预算内改正。工具处理过程无法确认结果时，停止 Run 并报告受影响的调用及停止原因。A 的每次模型请求或工具调用只尝试一次。 [工具调用、回执与恢复契约](tool-call-lifecycle.md)

运行器逐次分配 Run 余额。模型输出与工具回执共用额度，工具扫描及原始输出单独计量。已有的完整消息及执行摘要随终态返回。 [Run 预算、超限与收尾](run-budget.md)

## 流式输出与终态

运行器按 Run 独立排序事件。TUI 用实时流更新界面，切换视图或断开观察时，后台 Run 继续推进。事件发布时机、工具结局和订阅规则见 [SDK 事件与结果契约](go-sdk-contract.md#事件和结果)。

## 取消与在途工作

运行器为每次 Run 建立可取消的 `context.Context`，经 Mesh 传给本地依赖。等待和观察可以单独结束。主动取消发给拥有该 Run 的运行器，影响该 Run 及其子任务。 [Go context](https://pkg.go.dev/context#pkg-overview) · [Mesh 取消与断连](mesh-transport.md#取消和断连)

按 Run 裁决取消、工具派发和终态提交的先后顺序。取消生效后停止开始新步骤，并向已派发的模型、工具和环境工作传递取消。进程内 Go 工具需配合上下文，沙箱或远程环境可按其能力终止在途进程。工具派发后遇到取消、超时或掉线，若无法确认外部操作是否生效，则记录工具结果不明和停止原因。终态提交后保持固定。

## 待确认的取舍

| 顺序 | 决策 | 当前建议与代价 |
| --- | --- | --- |
| 1 | 谁推进循环，哪些工具可直接执行 | 内核推进完整循环，宿主按 Run 授予工具，跳过逐次人工审批。接入简单，宿主需要把可用工具与各自的业务权限配置清楚 |
| 2 | 同轮工具顺序及结果不明时的动作 | 同一 Run 内串行，独立 Run 并行。工具明确失败可交回模型修正，结果不明则停止。优先让调用顺序和外部效果可判断 |
| 3 | 进度对慢消费者的保证 | 使用有界流和独立终态接口。消费者太慢时需处理流中断，以换取运行继续推进且内存有界 |
| 4 | Mesh 的首版范围 | 先验证进程内分派及流式结果，用测试传输替身注入故障。远程只预留传输接口，线协议与部署范围单独评审 |
| 5 | 首个模型适配器 | 先用可控模型验收内核，再用一种真实模型验证流与工具回传。具体厂商另行评审 |
