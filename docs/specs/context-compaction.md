# 上下文压缩算法设计

设计评审稿。阶段 A 基线使用宿主选定的固定历史快照。本文定义后续可选的 Run 内压缩，由运行器在构造模型请求时调度，模型适配器提供窗口信息和计量。压缩生成模型可见的上下文视图，`Result.Messages` 仍从原始已提交消息生成。 [消息组装契约](message-assembly.md)

本地闭环与真实供应商冒烟通过后单独接入。 [上下文压缩接入门槛](stage-a-acceptance.md#上下文压缩接入门槛)

## 参数与触发点

| 参数 | 参与方式 |
| --- | --- |
| `W` 上下文总窗口、`I` 输入上限 | 来自所选模型绑定。供应商有独立输入上限时使用 `I` |
| `R` 输出预留、`S` 安全余量 | `R` 覆盖供应商计入窗口的全部输出，与实际请求的输出配置一致。`S` 吸收估算误差 |
| `TriggerRatio`、`TargetRatio` | 分别确定开始压缩与压缩后期望达到的占用。须满足 `0 < TargetRatio < TriggerRatio < 1` |
| `KeepRecentTokens`、保护项 | 从最新完整块向前保留的原文预算。已传入本 Run 的所有用户消息、宿主固定的历史项和最近完整块属于保护项 |
| `SummaryMaxTokens`、`SummaryMaxBytes` | 限制摘要生成及注入体积。模型适配器和运行器均执行限额 |
| `MinSavedTokens`、`MaxCompactionsPerRun` | 控制软触发的最小收益及单次 Run 的压缩尝试次数 |

运行器在第一次和之后每次模型派发前检查，工具轮次须已经整批提交。模型适配器对**即将实际发送的请求**计量。开启压缩需要已知窗口和可校验的计量方式。 [计量与派发接口](context-compaction-contract.md#计量与发送)

```text
B = min(W - R, I) - S           # 没有独立输入上限时使用 W - R
F = floor(B * TriggerRatio)    # 软触发线
T = floor(B * TargetRatio)     # 压缩目标
L = min(单次模型输入字节上限, Run 剩余输入字节)
```

- 待发输入达到 `F` 时尝试主动压缩。超过 `B` 或 `L` 时，须先得到能满足硬限额的视图才可派发。模型次数、期限或输出预算已耗尽时直接按 Run 规则收尾。
- 每个已提交消息版本最多尝试一次。达到 `MaxCompactionsPerRun` 后沿用可发送的现有视图。压缩计划同受理时确定的模型绑定和策略一起固定。
- 试验起点建议 `TriggerRatio=0.90`、`TargetRatio=0.70`，从 `min(20,000, T × 25%)` 开始试验近期保留量。总窗口 128k、预留输出 8k、安全余量 4k、无独立输入上限时，`B=116k`、`F=104.4k`、`T=81.2k`。这些数值用于首轮验证。

## 压缩步骤

1. **划分完整块。** 助手工具声明和所有配对回执组成一个块。保护指令、工具定义、已接收的全部用户消息、宿主固定的历史项和最新完整块。近期窗口从最新完整块向前扩展，加入下一块会超 `KeepRecentTokens` 时停止。保护项所在的工具块一起保留，原文保持顺序。仅保护项已超硬限额时直接收尾。
2. **先缩减重复正文。** 从旧到新处理可压缩块。对可从获准产物恢复的旧正文，用产物引用及已提交结果中的结局和原因码替代。维持消息结构和 `CallID` 配对。达到目标后即可进入校验。
3. **再摘要较早的完整块。** 从最旧的候选开始扩大待摘要范围，考虑保留的旧摘要条目和新增摘要上限。选择第一个预计满足 `T` 和 `L` 的范围，达不到目标时可选第一个预计满足硬限额的范围。新增条目从原始块生成；需合并旧条目时回到其原文。找不到满足大小与预算的范围时跳过摘要调用。 [连续压缩契约](context-compaction-contract.md#连续压缩与切换)
4. **限制摘要调用。** 使用本次 Run 已授权的模型，分配独立 `Step`，关闭工具，最多调用一次。摘要输入、输出、调用次数和时间计入 Run 预算，发送前按上限为摘要及下一次正常请求留足额度。摘要记录目标与约束、决策、已确认操作及结果、待办和来源。工具执行状态以原回执为准。
5. **校验后切换。** 只接受合法的 `ModelCompleted(stop)` 和完整摘要，核对来源范围、原文保护及工具配对。摘要作为独立的历史数据段交给适配器，宿主指令和授权保持原值。对最终输入重新计量，须满足 `B` 和最新的 `L`。软触发还须节省至少 `MinSavedTokens`。运行器检查停止状态后原子切换视图。

## 失败与可观测性

| 条件 | 行为 |
| --- | --- |
| 摘要失败、无效、收益不足或预算不够 | 依次检查确定性缩减视图、补齐新增消息的上版视图、本次完整原文。按当前预算和计量结果裁决。 [具体回退顺序](context-compaction-contract.md#回退与终态) |
| 固定项与最近完整块已经超出硬限额 | 直接结束为 `BudgetExceeded`，保留完整历史与已提交轮次 |
| 供应商仍拒绝上下文大小 | 报告 `model_context_overflow`，记录估算与可获取的实测用量。该轮沿用一次尝试的契约 |
| 取消或超时先于视图切换 | 放弃候选，按原停止规则收尾。已有工具效果继续以原回执为准 |

有界诊断记录触发原因、压缩前后 token 与字节数、覆盖块范围、摘要调用消耗和耗时。原始消息、摘要和来源引用的访问约束沿用本次 Run。 [Run 预算与收尾](run-budget.md#超限与收尾)

## 验收

先跑 [接口验收用例](context-compaction-contract.md#验收用例)。再按模型用同一批长任务比较未压缩、只保留近期窗口和本方案，测任务完成率、原约束保留率、重复工具副作用、窗口超限率及含摘要开销的总 token、成本与时延。用固定输入和原始证据定位压缩导致的失败，再调整门槛或摘要规则。
