# 最小 TUI · 双会话验收

2026-11-28，macOS arm64，Go 1.24.3。使用真实伪终端发送按键并读取渲染画面。SDK 装配使用本地 Mesh、真实临时会话与检查点目录、可控模型和带持久回执的慢工具。

| 用例 | 观测 |
| --- | --- |
| 受理通知 | 延迟交付真实入队通知期间，乙一直显示「启动中」。收到通知后显示排队，授予后显示受理中，拿到原句柄才打开 `Observe`。SDK 重试与慢消费用例中原请求只受理一次 |
| 切换与草稿 | 甲的中文草稿和已保存答复在切回后仍可见。乙连按两次 `Enter` 只启动一次。两个会话的历史各推进一次 |
| 单名额交接 | 乙排队时持久预约、Run 流和模型派发为零。甲终止但仍为 v0 时，乙已输出并提交到 v1。队列满和等待超时显示不同状态，并恢复原输入 |
| 取消排队 | 在乙发送 `Esc` 紧跟 `Tab`。甲仍在慢工具，收到取消次数为零。乙恢复原草稿并保持 v0，甲随后结束，乙派发仍为零 |
| 双流与取消隔离 | 甲在后台新增的流片段切回可见，乙的内容留在乙。连发 `Esc`、`Tab` 后，原乙 Run 收到一次取消，甲收到零次且继续输出。两个 Run 各开一次 `Observe`、各提交一次 |
| 取消与受理竞争 | 迟到的排队通知无法覆盖取消。授予已成功、启动回执不明两种分支只取消原乙 `RunID`，启动和模型派发各一次。终态先到分支保持原成功结果。SDK 定向验证也确认受理前取消能清除未尝试预约 |
| 观察与历史收尾 | 注入观察溢出和一次保存失败。观察先保留原预览，随后以可信终态替换。甲保存失败时版本仍为 v0，连按 `Enter` 只重试一次，保存后为 v1。乙切回时可见原流并继续输出 |

## 复验

7 个伪终端用例、全量 Go 普通回归、全量 race、`go vet` 和 OpenSpec 严格校验均通过。独立命令二进制另用伪终端和回环 Messages SSE 服务验证，两个会话各发一次请求并分别完成。全量测试的 Anthropic 实连开关为 0。

```sh
go test -count=1 -run '^TestPTY' ./internal/tui
go test -count=1 -run '^TestStartProgress' ./sdk
go test -count=1 ./...
GORACE=atexit_sleep_ms=0 go test -race -count=1 ./...
go vet ./...
openspec validate --all --strict
```
